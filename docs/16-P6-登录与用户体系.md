## 一、先回答：右上角的「开发者」是必须存在的吗？

**不是。** 那是内部工具，不是产品功能。

想清楚它的真实用途只有两个：**比赛演示时给评委看 Agent 内部**、**本机排障**。
这两个场景都不需要在第一眼出现 —— 学习者看到导航栏上挂着「开发者」只会困惑。

所以做法是**能力保留、入口移走**：

| 状态 | 表现 |
|---|---|
| 默认 | **完全不存在**，顶栏只有品牌与账号 |
| `?dev=1` | 唤出 |
| `Ctrl / ⌘ + Shift + D` | 唤出/收起 |

唤出后会被记住（演示中途刷新不至于突然消失）。这两种方式都实测通过。

技术细节**一件没丢**，仍在面板里：action / 决策规则 / 是否强制 / 允许集合 /
模型提案与拦截 / mastery 前后 / trace / sources / notes / 各阶段耗时占比 / 接口清单。

## 二、用户体系怎么落的

### 核心判断：不需要动任何一张既有表

P0–P5 的学习数据（作答状态、讲法偏好、会话）全都挂在 **`learner_id` 这个字符串**上，
而不是挂在某个自增主键上。当时那么设计只是因为还没有用户概念，
但现在成了好事：**接入账号体系只要给每个账号分配一个自己的 `learner_id`，
学习数据就天然隔离了** —— `learner_kp_states` / `learner_profiles` / `sessions`
三张表一个字都不用改。

于是 `users` 表的职责被压缩到两件事：

1. 证明"你是你"（`username` + `password_hash`）
2. 告诉系统"你的学习数据在哪"（`learner_id`）

### 新表 `users`

| 列 | 说明 |
|---|---|
| `id` | 主键 |
| `username` | 登录名，唯一，**统一小写入库**（避免 Tom/tom 两个账号） |
| `password_hash` | bcrypt 哈希，**从不存明文或可逆密文** |
| `display_name` | 展示名，可中文 |
| `learner_id` | 唯一，随机生成（`u` + 16 位十六进制）——**不可枚举** |
| `is_active` | 停用账号用（不删数据） |
| `last_login_at` / `created_at` / `updated_at` | 时间戳 |

迁移：`alembic/versions/0006_p6_users.py`。索引只有 3 条
（PRIMARY + 两个唯一约束），**没有重复建索引** —— 唯一约束在 MySQL 里本身带索引。

### JWT 怎么用

**令牌放在 httpOnly Cookie 里，不放 localStorage，也不进 URL。**

这不是随手选的：项目自己定过那条规矩 —— 令牌进 localStorage 一旦 XSS 就会被读走。
放 httpOnly Cookie 之后，前端 JS 根本拿不到它，**不是"约定不要读"，是"读不到"**。

因此登录/注册的响应体里**只有用户信息，没有令牌**（有测试逐字段断言）。
脚本调用走 `Authorization: Bearer`。

Cookie 三个开关：`httponly`（挡 XSS）· `samesite=lax`（挡 CSRF；
用 lax 不用 strict，否则从外部链接进来第一次请求不带 Cookie，
会出现"明明登录了却显示未登录"）· `secure`（生产必须开，本机 http 演示关闭）。

**算法显式白名单**（`algorithms=["HS256"]`）：不指定的话，
攻击者可以把 header 改成 `alg: none` 绕过验签 —— JWT 最经典的坑。

### 口令为什么先过一道 SHA-256

bcrypt **只取前 72 字节**，超出部分静默丢弃。中文场景会真出事：
30 个汉字的口令就是 90 字节，后 18 字节等于没设。
所以先 `sha256` + base64（固定 44 字符）压进定义域。

### 顺手补掉的一个越权口子

引入账号之前，请求体 / 查询串里的 `learner_id` 是**被服务端直接采信**的 ——
那时候只有一个本地用户，无所谓。有了账号之后这就是一个越权读写口：
改一下请求体就能读写别人的学习记录。

现在的规则是：

```
已登录  → 用账号绑定的 learner_id（请求体里那个字段被忽略）
未登录  → 落到本地档案 local（同样是固定的，请求体说了不算）
```

字段本身保留在 schema 里（删掉会破坏契约），但**不再被读取**。
`/dashboard`、`/learner-state`、`/profile` 三处一处没漏。

## 三、前端

### 界面：读者登记卡

刻意不用"居中大圆角卡片 + 渐变 + 玻璃拟态"那套通用长相 ——
和「拾知」的暖纸书桌完全不是一路。延续同一套隐喻：
**品牌标识本来就是一截书签，登录页做成"在图书馆办一张证"**。

手法：左侧一道墨绿书脊把卡片"装订"起来、账本式页签切登录/注册、
标题用衬线、纸底加一层极淡的横格纹理（`repeating-linear-gradient` 画的，
不引图片不占体积）。

### 一个容易忽略的细节：首次要"确认"，不要"猜"

令牌在 httpOnly Cookie 里，JS 读不到，只能问一次后端。
如果不管这件事直接渲染登录页，已登录用户会看到登录页**闪一下**再跳走。
所以有 `checking` 态：确认期间显示品牌标记的安静过渡，确认完再决定去哪。

### 换账号必须整体重置

`LearningProvider` 用 `user.id` 当 key —— 换账号时整体重挂载，
看板、会话、掌握度全部重置。**这比在每个状态里手动清理安全得多**，
是防止"上一个人的学习状态漏到下一个人界面上"最可靠的做法。

### 演示账号

播种脚本 `scripts/seed_demo_user.py`，它的 `learner_id` **显式指定为 `local`** ——
P0–P5 攒下的样例学习数据都挂在这个标识上。登录演示账号就能看到全部记录。

口令**从 `.env` 读**（`DEMO_USERNAME` / `DEMO_PASSWORD`），代码里不写死；
没配就报错退出，不猜默认值 —— 默认口令是账号体系最典型的失守点。

## 四、顺手修掉的一个真 bug

测试登录失败路径时，界面上显示了：**「出了点问题，没能完成这一步。（HTTP undefined undefined）」**

原因：`postJson` 抛出来的已经是**提取好消息的普通 `Error`**，
而我在上层又把它当 `Response` 解析了一遍 → `res.status` 是 undefined。

这个错误用法在项目里散布了 **10 处**（学习页、知识地图、资料页都有），
全都不是这次引入的，一直潜伏着。已统一收敛到一个 `messageOf(err)`，
并写明为什么需要它。

## 六、需要你知道的两件事

**1. 演示账号的口令在项目根 `.env` 里**（`DEMO_USERNAME` / `DEMO_PASSWORD`）。
按项目约定，口令不写进任何代码、文档或报告 —— 需要登录时从 `.env` 取。

**2. `JWT_SECRET` 也在 `.env`，是随机生成的。**
换掉它会让**所有已登录用户立刻掉线** —— 这正是"密钥疑似泄露要立刻轮换"的手段。
没配置时后端会打警告并使用本次进程的临时密钥（表现为"重启后全部掉线"），
不会静默用一个弱密钥长期跑。

## 七、仍存在的问题

1. **JWT 无法真正吊销**。签出去的令牌在过期前技术上仍然有效，
   这是无状态令牌的固有性质。要真吊销需要令牌黑名单或改为服务端会话。
   目前的缓解是把有效期设成 7 天而不是更长。（改密码也**不会**让旧令牌失效。）
2. **没有找回密码** —— 没有邮箱/手机，无法自助重置。当前只能由管理员改库。
3. **没有登录频率限制**，理论上可暴力尝试。本地演示无碍，上线前必须加。
4. **匿名接口仍可用** —— 这是刻意的（保既有契约、便于接口文档试用），
   产品层面靠前端路由守卫拦住。若将来要"接口层强制登录"，
   给这些路由加上 `CurrentUser` 依赖即可，改动很小。
5. Cookie 的 `secure` 现在是 `false`（本机 http 演示需要）。**上线必须改成 true。**

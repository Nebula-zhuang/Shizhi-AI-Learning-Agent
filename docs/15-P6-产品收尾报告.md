## 【当前问题】

先审查再动手。审查方式是**跑真实 Qwen、逐轮读实际生成的内容**，不是读代码。

### 问题 1（最严重）：提问不自述，学习者不知道要答什么

实测原文（改造前）：

> 那么：进程和线程，分别是谁在分配资源、谁在被调度？

问题本身不算差，但学习者**不知道要答到什么程度算过**：
要答几点？要不要展开？用定义还是例子？只能猜。这正是你说的
"不要让用户猜 AI 到底想让我说什么"。

### 问题 2（最严重）：连续受挫时反复问同一句话，学习者卡死

连续三轮 `easier`，三轮都在问同一道二选一：

| 轮次 | 助教的反馈（原文摘录） |
|---|---|
| 1 | "问题只问'进程是静态的代码，还是动态的执行过程？'……**你没回答这个二选一**" |
| 2 | "题目直接问'进程是动态执行过程，还是静态代码？'……**你没回答问题本身**" |
| 3 | "问题只问'进程是动态执行过程还是静态代码'……**你没回答问题本身**" |

三轮问的是同一句话。学习者的回答一直没对上，**而系统没有任何改变**。
这不是模型的问题 —— `easier` 的提示词只要求"问一个最小的问题"，
没告诉它"上一轮问过了就别再问"。这是提示词的漏洞。

### 问题 3：策略层的内部理由直接端给学习者

我给主界面加了「接下来：」这句（你要求的第 4 点），但用的是后端的 `turn.reason`。实测原文：

> 学习者刚答对且理解标准差与波动性的关系，需 **probing** 确认是否能迁移至偏度/峰度
> 等其他统计量的解释。

两个问题：**用第三人称谈论学习者**（"学习者刚答对"），**泄漏内部动作名**（probing）。

### 问题 4：流式路径把原始 JSON 显示到了界面上

接入流式生成时，我在提示词末尾**追加**了"直接输出正文，不要 JSON 包装"，
但提示词里原有的"输出 JSON：`{"content": "..."}`"还在。**两条相反的指令里先出现的赢** ——
模型照做了前者，界面上直接显示：

```
{"content": "这道题问的是：……"}
```

### 问题 5：主界面的开发语言（上一轮已清，这轮复查）

`mastery` 数值、教学动作徽章（"讲一讲""放慢一点"）、状态机轨迹、工具调用、
命中规则、相似度、置信度 —— 都还在用户能看到的地方。

### 问题 6：左栏被待复习撑满，课程导航被挤出可视区

到期待复习有 6 条时，左栏整屏都是书签卡，"学什么"（课程/章节/知识点）完全看不见。

### 问题 7：响应慢且长时间无反馈

实测一轮 7.5 秒，期间界面只有一个"助教在想…"。

## 【修改内容】

### 一、Tutor 教学体验

**问题 1 的修法**：在 `tutor_actions.md` 里立了一条硬规则 ——
**只要这一轮要学习者作答，正文最后必须写清三件事，然后才是问题本身**：

1. **问什么** —— 一句话说清这道题在问什么
2. **要答到** —— 列出 1–3 个必须覆盖的关键点，用 ①②③ 编号
3. **怎么答** —— 说清形式（用自己的话 / 二选一 / 举例 / 说清区别）

并给了明确的**反例清单**（"说说你的理解""介绍一下这个概念""你还有什么补充吗"）
与两个正确示范。

改造后实测（原文）：

> 这道题问的是：进程和线程，谁负责分配资源、谁负责被CPU调度？
>
> 要答到两点：
> ① 哪个是"资源分配单位"（从资料里直接找原话）
> ② 哪个是"调度单位"（也从资料里直接找原话）
>
> 用两个短句回答，比如："X是资源分配单位；Y是调度单位。"
>
> 那么：进程和线程，谁是资源分配单位？谁是调度单位？

**问题 2 的修法**：加了「**不要重复问同一句话**」一节，写清判断依据
（上一轮评估里的 `missing_points` / `misunderstood_points`）与四种换法
（换更小的切入角度 / 换问法 / 给半个答案让他补 / 先澄清题目要求），
并特别点明 `easier` 是最容易踩这条的动作。

**问题 3 的修法**：前端按**命中的规则**自己组人话（`nextStepWords`），
不再复述后端的理由文本。规则名（R1–R8）是稳定字段，比解析自然语言稳健得多。

| 命中规则 | 学习者看到的话 |
|---|---|
| R1_mastered | 这块你已经稳住了，我把要点收一收，这次就学到这里。 |
| R2_wrong_streak_3 | 连着卡了几次，我们退一步，先把最基础的那一步垫实。 |
| R3_wrong_streak_2 | 刚才那种讲法没通，我换个角度再讲一遍。 |
| R5_correct_streak_2 | 你连着答对了几次，我把难度提一档，看看能不能稳住。 |

**问题 5 的修法（教学动作不再暴露）**：删掉主界面上的动作标记，
`explain/probe/rephrase/harder/easier/summarize` 只保留在返回体与开发者面板里。
换了讲法，学习者从内容里读出来（"换个角度……"），不是从徽章上读出来。

右栏的「本次学习轨迹」也改成了**记录学习者自己的表现**（答对/没答对 + 错因），
而不是记录系统用了哪个策略。

### 二、响应速度

**先测量，再优化。** 新增 `scripts/measure_turn_latency.py`，
从返回体的工具留痕里拆出每一段耗时。

发现：**一轮 7.5 秒里 89% 是三次串行 LLM 调用**。

| 阶段 | 中位耗时 | 占比 |
|---|---|---|
| 评估作答 | 3654 ms | 49% |
| 决策下一动作 | 1857 ms | 25% |
| 生成内容 | 1147 ms | 15% |
| RAG 检索 | 439 ms | 6% |
| 状态读写 | ~26 ms | <1% |

**优化 1：把 RAG 检索藏进评估里（已做）。**
关键观察：**检索的入参只有知识点本身**（标题+摘要），既不依赖评估结果、
也不依赖决策结果 —— 所以它可以提到"评估作答"之前并发跑。
评估要 3.6 秒，检索只要 0.4 秒，整段被完全遮住。

**优化 2：开课轮让检索与决策并发（已做）。**

**关于"为什么不合并决策与生成"** —— 认真考虑过，**否决**：
合并后模型会先定动作再生成内容，而**动作可能被 Policy 改掉**，
内容就对不上了。当前架构保证"生成的内容一定对应最终生效的动作"，
这个保证比省 1.8 秒重要。

**关于"为什么不跳过被强制轮的决策调用"** —— 也**否决**：
跳过会让"Agent 提案 + Policy 校验"这条链路在部分轮次上不存在，
"阈值不可被绕过"就只被验证了一半。

**真正的感知优化：流式。** 新增两个接口（原有接口一行未改）：

- `POST /api/tutor/start/stream`
- `POST /api/tutor/answer/stream`

推三种帧：
- `stage` —— 真实阶段（来自运行时状态机，**不是假进度条**）
- `content` —— 正文文字增量（边生成边显示）
- `done` —— 最终响应体，与同步接口**完全一致**

阶段映射写在 `STAGE_LABEL`：ASSESS→"正在看你的回答…"、
RETRIEVE→"正在翻你的资料…"、DECIDE_ACTION→"正在想下一步怎么教…"、
EXECUTE_ACTION→"正在组织讲解…"。读状态/读记忆只要几毫秒，**刻意不报**
（报出去只会闪一下，反而显得界面不稳）。

### 三、用户界面

主界面**一个技术词都不出现**（审计结果见下）。清掉的：

| 原来 | 现在 |
|---|---|
| `mastery 0.00` / 掌握程度 **24%** | "现在到什么程度：快了，再稳一稳" + 进度条（无数值） |
| 动作徽章「讲一讲」「放慢一点」 | 无（策略内部化） |
| 轨迹里的 "↑ 30%" | "有进步" / "有点退" |
| 「为什么这样教」折叠区里的状态机/命中规则/工具调用/阈值 | **全部移进开发者面板** |
| 后端 `reason`（第三人称 + probing） | 前端按规则组的人话 |

技术细节**一件没丢**，全在开发者面板里（按 `\` 或点右上角"开发者"）：
action / 决策规则 / 是否强制 / 允许集合 / 模型提案与拦截 / mastery 前后值 /
trace / sources / notes / **各阶段耗时与占比** / 接口清单。

## 【响应耗时】

真实 Qwen（qwen-plus），单轮作答：

| 阶段 | 中位耗时 | 说明 |
|---|---|---|
| 评估作答 | 3.7 s | LLM |
| **RAG 检索** | **0.35 s** | **已被评估完全遮住（并发）** |
| 决策下一动作 | 1.7–2.1 s | LLM |
| 生成内容 | 1.5–2.9 s | LLM，**流式** |
| **总计** | **7.0–9.0 s**（改造前 7.5–13.4 s） | |

**感知耗时（这才是关键）**：

| 时刻 | 界面上发生什么 |
|---|---|
| 4 ms | 第一帧"正在看你的回答…"到达 —— **完全不白屏** |
| ~3.8 s | "正在记下这次的结果…/正在翻你的资料…/正在想下一步怎么教…" |
| ~5.5 s | "正在组织讲解…" |
| ~5.8 s | **正文开始逐字出现**，学习者开始阅读 |
| ~7.0 s | 完成 |

也就是说：**学习者从 5.8 秒起就在读内容了**，而不是干等到 7 秒才看到第一个字。

诚实说明：**关键路径仍是三段串行 LLM 调用，计算量没变**。
再快只有两条路 —— 换更快的模型，或合并决策与生成（已论证会破坏
"内容一定对应最终动作"的保证）。按你的要求"优先优化调用链、不第一时间换模型"，
本轮走到这里。

## 【仍存在的问题】

**1. 关键路径没有本质变快。** 7–9 秒里 89% 是 LLM 延迟。
流式解决了"看起来卡住"，没解决"它就是慢"。若要压到 3 秒内，需要换模型
或改架构（合并决策+生成，但有正确性代价）。

**2. 「不要重复问同一句话」只靠提示词约束。** 加了明确指令并在实测中生效，
但这是**软约束** —— 模型仍可能偶发重复。要硬保证得在代码里比对上一轮问句，
那属于新增业务逻辑，本轮没做。

**3. 提问结构是自然语言，不是结构化字段。** "问什么/要答到/怎么答"是靠提示词
组织成段落的，前端不做解析。好处是不改 API 契约、渲染简单；
代价是不同轮次的排版可能略有出入（实测三份样例都稳定）。

**4. 视口小时中栏偏挤。** 自动化截图工具的窗口固定 1262×568，
这个高度下中栏对话区只有约 180px。演示屏（1920×1080）不会遇到，
但小笔记本上会。窄屏降级策略是"单列纵向排列"，没细调。

**5. 加载态仍是文字而非骨架屏。** 现在有真实阶段话术，观感已可接受，
但资料页解析、索引这些地方还是纯文字提示。

**6. 资料页与知识地图的空状态**还没统一到新语言。

**7. 核验判定过严（遗留，需你决策）。** qwen-plus 下 12 个知识点里 10 个被判「存疑」——
把"原文没逐字写出"当成了"可能错了"。演示时会显得整份资料都不可信。
属于 P2 业务行为，**未改动**。建议调 Prompt 判定口径，区分
「原文未直接支持」与「与原文冲突」。

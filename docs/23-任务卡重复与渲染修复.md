## 一、内容重复：根因与修法

### 现象

同一个知识点出现两次：引导语在卡片里渲染一遍，又在卡片下方渲染一遍。

### 根因

`TaskCard` 有两个数据来源：

```js
const leftover = uncoveredLines(content, card)   // ← 兜底行
```

`uncoveredLines` 的设计意图是"兜住解析漏掉的行，不要静默丢句"。但它的实现是：

```js
remember(card.lead)              // 记下的是**整段拼接后的字符串**
…
return rows.filter(row => !covered.has(row))   // 却拿**单行**去比对
```

**永远匹配不上** → 每一行都被判成"没覆盖" → 全部再渲染一遍。

实测那 634 字的真实内容，`uncoveredLines` 返回了 **8 行**，正是全部引导语。

### 修法：把 leftover 交回解析函数

不再让调用方"另算一遍"，而是**由 `parseTaskCard` 自己产出**：

```ts
interface TaskCard {
  leadLines: string[]   // 逐行保留，与 lead 同源
  leftover: string[]    // 解析时顺手记下谁没被接住
}
```

**"算覆盖"与"做分区"从此是同一份逻辑**，不存在两边对不上的可能。
`uncoveredLines` 保留为兼容导出，但内部直接返回 `card.leftover`。

另外引导语改为**逐行渲染** —— 之前拼成一整段，HTML 会把换行折掉，
「是什么 / 为什么 / 怎么用」三个小标题会糊成一大坨。

## 二、回答方式的三层误判（都是真实踩出来的）

「怎么答」这一栏被误填过三次，每次修完又冒出新反例。记录在这里，因为它们解释了现在规则为什么长这样：

### 第一轮：只看语汇 → 长段解释被误判

真实内容里有一句：

> 为了解耦和扩展：调用者不依赖具体国籍类…只要它实现了 `Human` 接口**就行**。

`就行` 命中了 how-to 语汇 → 这段「为什么用」被塞进了【怎么答】。
**看起来就像同一段话出现了两遍。**

### 第二轮：加长度限制 → 描述字数的句子又被误判

收紧为"短 + 命中语汇"后：

> 图表作文的 Overview 段落，是**用 1–2 句话**高度凝练图表中最突出的动态特征的独立段落。

这句 42 字、含"用…句话"，又中了。**它其实是在讲字数要求，属于铺垫。**

### 第三轮：加位置限制 → 才对

观察真实输出结构，稳定是：

```
铺垫讲解  →  要答到：  →  要点清单  →  怎么答  →  那么：问题？
```

**回答方式永远在要点之后**，而上面那句描述属于铺垫，排在要点之前。

于是规则定型为**三条缺一不可**，并附上前两轮的原文作为测试用例：

```
短（≤44 字）  +  命中语汇  +  排在要点之后（若无要点区段则不设限）
```

### 顺带修的：`要答到三点：` 不是要点

模型常写：

```
要答到三点：
① 它必须概括几个总体趋势（填数字）
② …
```

我的解析把 `三点：` 当成了第 1 个要点，于是真实要点被挤成 **2/3/4** —— 用户看到的编号是错的。
加了 `isPointLabel()`：以冒号结尾、或纯粹是「三点 / 以下 3 点」这类计数的，一律视为区段标签。

## 三、反引号清理

教学内容是当**纯文本**渲染的（`<p>{line}</p>`），所以 `` `Human` `` 会连着反引号一起显示。

新增 `stripInlineMarkup()`：摘掉反引号与星号强调标记，**但保留内容本身**：
`` `Human` `` → `Human`，`**重点**` → `重点`。

乘号刻意不误伤：单星强调的规则要求两侧都不是星号，所以 `2*3` 原样保留。

同时在提示词里加了一条（第 7 条）：让模型**直接写标识符、不要加反引号** ——
前后端各做一层，谁都不指望对方。

## 四、「开始作答」按钮

之前 `onStart` 指向 `() => setPickerOpen(false)` —— **一个和它毫无关系的空操作**，所以按了没反应。

现在：把光标送进作答框，并平滑滚动到可见。

```ts
const focusAnswer = () => {
  const el = answerRef.current
  if (!el) return
  el.scrollIntoView({ behavior: 'smooth', block: 'center' })
  el.focus()
}
```

按钮如果按了什么都不做，用户会当成"坏了"。它该做的是**把注意力接过去**。

## 五、提示词补强

通用要求里新增第 6 条：

> **同一件事只讲一遍。** 讲完之后提问时，**不要把那句解释再复述一次**。
> 实测出现过：先写了"是什么 / 为什么 / 怎么用"，提问时又把整段话抄了一遍 ——
> 学习者看到的是同一段内容出现两次，会以为自己看错了。
> 提问只需要三件事：这道题问什么、要答到哪几点、怎么答。

## 九、一点反思

这三个 bug 全都出在 `taskCard.ts`，而它此前**一条测试都没有**。

它的处境其实很危险：**解析的是模型输出**，输入不可预测；但又必须"拆不动就退化成散文"，
所以失败不会报错、只会静默地渲染错东西 —— 正是最需要测试的那类代码。

现在的 21 条用例里，最重要的是把**真实踩过的原文**直接钉进去：

- 含「就行」的长段解释 → 必须留在引导语
- 含「用 1–2 句话」的描述句 → 必须留在引导语
- 含「要答到三点：」的输出 → 要点必须是 3 条而不是 4 条

这样下次再调规则时，会把当时为什么这么写一起带上。

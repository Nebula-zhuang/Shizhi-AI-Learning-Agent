# 资料归属隔离修复

> 日期：2026-09-19
> 用户反馈：**「不是一个账号一个数据吗，为什么我注册了的账号都共享了一份数据」**
> 结论：**是真 bug，我之前说"数据隔离"说得太满了。** 已修复。

---

## 一、问题出在哪

我先复现，`localhost:5173`（用户用的地址）下逐项查：

| 检查项 | 结果 |
|---|---|
| 登录态（httpOnly Cookie） | ✅ 正常，`/api/auth/me` 返回正确身份 |
| 学习看板（掌握度、待复习、薄弱点） | ✅ **按账号隔离**（新账号 已追踪=0） |
| **资料列表** | ❌ **看到全部 7 份** |

根因：**`documents` 表根本没有归属字段。**

P0–P5 没有账号概念，资料天然是"这一个用户的"。P6 接入账号时，
我只把 `learner_id` 绑到了**学习状态**（`learner_kp_states` / `learner_profiles` /
`sessions` 三张表），**漏了资料**。所以：

- 学习进度 → 隔离 ✅
- 资料库 → 全局共享 ❌

用户注册新账号后一进「资料」「知识地图」就看到别人的文件，
自然会问"为什么共享了一份数据"。

**我之前的表述不够准确**：我说"给每个账号分配一个 learner_id，学习数据就天然隔离了"——
那句话对**学习数据**成立，但我没意识到资料不在这套体系里。这是我的疏漏。

---

## 二、怎么修的

给 `documents` 加 `owner_learner_id`，**资料也按账号隔离**。

### 数据库

迁移 `0007_p6_document_owner`：

- 新增 `owner_learner_id varchar(64) NOT NULL DEFAULT 'local'` + 索引
- **用 `server_default` 而不是可空**，两个理由：
  1. 既有行自动回填成 `local`，于是演示账号（它的 learner_id 也是 `local`）
     仍看得到 P0–P5 攒下的样例资料，演示不受影响；
  2. **不允许"无主资料"存在** —— 若允许 NULL，将来任何一处忘带 owner 的查询
     都会把无主资料当成"谁都能看"，等于留个后门。

### 服务层（`document_service`）

| 函数 | 改动 |
|---|---|
| `find_by_hash` | **按账号查重** —— 否则 B 传一个和 A 相同的文件会命中 A 的记录，B 反而拿不到 |
| `create_document` | 记下 `owner_learner_id`（默认 `local`，匿名上传走这条路） |
| `get_document` | 可选传 `learner_id`，**同时校验归属** |
| `list_documents` | 只返回该账号自己的 |

### 接口层

统一两个 helper（放在 `app/api/deps.py`）：

- `require_document(db, id, learner_id)`
- `require_knowledge_point(db, kp_id, learner_id)` —— 知识点没有归属字段，
  归属顺着 `knowledge_points.document_id → documents.owner_learner_id` 判

**不属于当前账号的一律返回 404，而不是 403。** 403 等于告诉对方
"这个 id 确实存在"，那就成了一个用来探测别人资料的工具。

接线的接口：`/documents` 全套（9 个）、`/documents/{id}/graph|verify|relations`、
`/knowledge-points/{id}`（详情 / checks / relations）、`/tutor/start`、
`/tutor/learner-state/{id}`、`/rag/sources`。

### 两个容易忽略的洞

**① `/rag/ask` 省略 `document_ids` 时会搜全库。**

`answer_question` 里是 `if document_ids:` —— 空列表是 falsy，
会被当成"不限范围"。所以不能把"我的资料列表为空"直接传进去，
否则绕一圈又回到全库检索。改成：范围为空就明确告知"你还没有上传资料"（409）。

**② 授权该放路由层，不该塞进运行时。**

一开始想直接在 `TutorRuntime.start` 里校验知识点归属，但那样错了：
运行时的职责是**教学**，而且它也被测试与脚本直接调用（那边没有账号上下文）。
所以校验放在路由里，调用运行时之前。

### 新增回归测试 `tests/api/test_document_isolation.py`（10 个用例）

补这一组的原因就是这次的缺口 —— 把它固定住，以后改坏会立刻红：

- 新账号资料库必须为空
- **演示账号仍能看到样例资料**（防"修隔离时把演示数据也一起挡掉"）
- A 的资料 B 看不到（列表）
- **按 id 直取也要挡住**：详情 / 状态 / 结构 / 块 / 删除 逐条断言 404
- 知识点按 id 直取挡住（详情 / checks / relations / learner-state / **教学入口**）
- 本人读自己的资料必须正常（防误伤）
- 同 hash 文件在两个账号间**不互相命中**
- 检索范围不退化成全库
- 模型层与业务层用的是**同一个**默认标识

## 四、你需要知道的一件事

**你现在已有的 `admin`、`adasdas` 两个账号，资料库会变成空的** ——
因为它们是在修复前注册的，而当时所有资料都归 `local`。

- 想看样例数据：用 **`demo`** 账号登录（它绑的就是 `local`）
- 想在自己的账号里看到资料：在「资料」页**重新上传**即可，上传后就归你

这是正确行为（新账号本来就该是干净的），但和你昨天看到的不一样，先说一声。

如果你希望"新注册的账号自动获得一份样例资料库"，那是另一种产品设计
（相当于给新用户一份 demo 内容），我可以做，但需要你确认 —— 因为
那意味着**每个新账号都会有一份 7 份资料的副本**，存储和向量索引都会翻倍。

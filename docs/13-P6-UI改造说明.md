## 一、一件先办的事：把演示从 mock 里救出来

P5 结束时因为 DeepSeek 余额不足，`.env` 被固定成 `LLM_MODE=mock`。
但 **mock 模式没法演示**：知识点标题会带 `[MOCK]` 前缀、教学内容是模板生成的。

好消息是：你给的 embedding Key 来自**阿里云百炼**，同一个端点也提供 Qwen 对话模型。
新增探针脚本一试，三个模型全通：

```
python scripts/probe_llm.py
  阿里云百炼 · qwen-plus     ✔ 可用  返回：'可以'
  阿里云百炼 · qwen-turbo    ✔ 可用
  阿里云百炼 · qwen-max      ✔ 可用
```

**已把 `.env` 切到 `qwen-plus`**（与 embedding 同一个 Key、同一个端点）。
DeepSeek 的三行配置以注释形式留在原处，充值后换回去即可。

效果立竿见影 —— 同一份资料，重新抽取：

| 教材知识点 | 6 个 | **12 个** |

## 二、样例资料包

`python scripts/make_samples.py` → 生成到 `samples/`；`python scripts/load_samples.py` → 装载。

### 主题：操作系统 · 进程管理

选它的理由（四件事全占，换成任何一门有"概念对比"的课都能用）：

- **有真实辨析点**：进程 vs 线程、就绪 vs 阻塞、死锁四条件 → 追问问得下去
- **有经典误区**：学习者常把"资源分配单位"和"调度单位"记反 → 薄弱点可信
- **有可核验事实**：死锁四条件是学科共识 → 演示核验有东西可查
- **章节层级清晰**：三级标题结构 → 图谱能分出好看的章节带

### 三份资料，各司其职

| 文件 | 分量 | 演示什么 |
|---|---|---|
| `操作系统原理-第3章-进程与线程.pdf` | 7 页 / 12 个知识点 / 13 条关系 | **主资料**：解析 → 知识点 → 章节层级 → 图谱分带 → Tutor 追问 |
| `操作系统实验指导书-实验二.pdf` | 5 页 / 6 个知识点 | 第二份资料：多资料入库、跨资料关系 |
| `复习笔记-进程管理常见误区.txt` | **故意含 3 处错误陈述** | 可信度核验：那三处应被判为可疑 |

生成时做了两件必要的处理：

1. **必须嵌入 CJK 字体**，否则中文提取回来是乱码（P1 就踩过，这里沿用 `china-s`）。
2. **字体子集化**：`insert_font` 会把整份中文字体嵌进每一页，
   不做 `subset_fonts()` 的话一份 7 页讲义有 **3.5 MB** —— 压到 481 KB。

## 三、UI/UX 改造

### 3.1 设计方向：**「书桌与批注」**

产品定位是「读懂你的资料、验证你的知识、并主动带着你学会的私人助教」——
所以界面不该是后台，而该是**一张摊开的书桌**：你的资料摊在那儿，
助教在手边批注、追问、提醒你哪里该重看。

三条从定位直接推出来的规则：

1. **暖纸而不是纯白。** 纯白 + 冷灰是"管理后台"的默认皮肤；
   纸的暖调让界面有"在读东西"而不是"在操作数据"的感觉。
2. **衬线标题 + 无衬线正文。** 标题有"书"的气质，正文保持屏幕阅读效率。
   用 `Noto Serif SC` / `Noto Sans SC` —— **本机已装，不走网络**，演示现场不怕断网。
3. **信息要像人说的话。** 每个数字旁边都应该有一句人话。

### 3.2 记忆点：书签

**待复习清单做成"书签"形态** —— 从卡片左缘探出的一小截暖色标签。
隐喻很直接：**"我帮你夹在这里了。"**

这个形状同时是**品牌标识**（`BrandMark` 就是一枚书签）与**功能元素**（`.bookmark`）。
一个形状同时承担品牌识别与产品功能，比再画一个抽象图标更省力也更结实。

### 3.3 设计令牌

全部集中在 `src/styles/theme.css`，颜色 / 字体 / 字号 / 圆角 / 阴影 / 缓动六组。

几个关键取舍：

- **`moss`（墨绿）同时是主色和"已掌握"色** —— 在这个产品里，
  绿色按钮和"学会了"本来就是同一件事。
- **`ink-4` 明确不承载信息**，只做装饰；其余墨色在纸底上的对比度都 ≥ 4.5:1。
- **暖色调阴影**（褐色 alpha）。冷灰阴影落在暖纸底上会显脏。
- **圆角克制**（3/5/8/12/16）。过大的圆角是"通用 SaaS 卡片"的标志。
- **最小字号 12px**。原界面大量使用 10/11px。

### 3.4 外壳：把后台感去掉

| 原来 | 现在 |
|---|---|
| 标题写"阶段 P5：跨会话长期记忆 · 遗忘曲线…" | `你的私人学习伙伴 · 读懂你的资料，带着你学会` |
| 顶部常驻 4 个组件健康徽章（MySQL / Chroma / embedding…） | 收进右上角「开发者」折叠面板 |
| 底部列 `/api/documents`、`/api/rag/ask` 等接口 | 移入开发者面板 |
| 导航：`资料库 / 知识图谱 / Tutor 学习 / 对话调试` | `学习 / 资料 / 知识地图`，`接口调试` 降级进开发者面板 |
| 默认落在「资料库」 | 默认落在「学习」—— 产品是学习伙伴，不是文件管理器 |

定位文案同步更新到浏览器标签页（这是用户唯一会长期看到的一句话）。

### 3.5 Tutor 学习页（重写）

一整页只服务一件事：**让"这不是搜索框，是记得住你的助教"成立。**

**书桌视图**（没在学的时候）：

- 助教的开场白**完全由真实数据拼出来**，不是写死的欢迎语：
  「中午好，有 3 个知识点到了该复习的时候。我把它们夹在下面了，要不要先看一眼？」
  没有资料时它会说「还没有读过任何资料。先把课件传上来，我读一遍」——
  **不会说出"从你的资料里挑一个"但根本没资料这种假话。**
- 待复习 = 书签卡片，每条给出「连错 3 次，卡在概念混淆 · 2 小时前该看了」
- 薄弱点 = 「这些地方你摔过跟头」
- 学习情况 = 三个有意义的状态给大号衬线数字，"还没碰过"降到脚注

**对话视图**（在学的时候）：

- 助教说的话用**衬线大字**（像书上的注解），学习者的话用**右侧浅底气泡**（像自己写的笔记）
  —— 靠排版分"谁在说"，不靠气泡颜色
- 回顾卡片 = **页边批注形态**：左侧一道赭色竖线 + 衬线字，
  是"有人记得你"，不是"系统告警"
- 教学动作用一条安静的注脚（`—— 换讲法`），不再是徽章墙
- 每轮消息下方有「**为什么这样教**」折叠区

### 3.6 开发信息去哪了：**收起，不是删掉**

P4/P5 攒下的排障信息全部保留，只是默认不占据视线：

| 信息 | 去向 |
|---|---|
| 组件健康、接口清单、接口文档 | 顶部「开发者」面板（`DevPanel`，也可按 `\` 切换） |
| 状态机轨迹、命中规则、模型提案校验、工具调用、掌握度变化 | 每轮消息下方「为什么这样教」折叠区 |
| 直连 LLM 网关的流式验证 | 开发者模式下的「接口调试」标签页 |

演示干净，排障不缺。

## 四、改造中修掉的问题

### 4.1 脚本替换色值把 SVG 改黑（值得记住的教训）

批量替换十六进制色值时，`#ffffffd9` 被改成了非法的 `#fffdf9df9`（长度不对）。
浏览器遇到非法 `fill` 会**忽略该属性、回退成黑色填充** ——
知识地图整块画布变成黑的，像在暖纸上挖了个洞。

**脚本不会告诉你这件事，截图会。** 所以纪律里加了一条：
批量改样式之后必须肉眼过一遍每个页面。（这条已写进 `.impeccable.md`）

### 4.2 状态徽章被挤成两行

「已完成」在窄卡片里折成了「已完/成」。原因是徽章没有 `shrink-0`，
和可伸缩的文件名同处一行时被压缩。已在 `StatusBadge` 层面修掉 ——
徽章**永远不该折行**，不管用在哪里。

### 4.3 回顾语显示了两遍

P5 的后端为了"跨会话记得住"会把回顾语**拼进正文**，同时又通过 `memory.recall_note`
单独返回。新界面用更合适的样子把它渲染成页边批注卡片后，正文里那一份就成了重复 ——
学习者会看到同一段话读两遍。

**只在前端剥离**（`stripRecallPrefix`）：不动接口、不动后端行为，
只是选择不重复展示同一份数据。

### 4.4 "还没开始"与"连错 3 次"同时出现

掌握度 0 有两种完全不同的处境：**从没学过**，和**学了但一次没答对**。
原来的 `masteryWords(0)` 一律返回"还没开始"，于是同一个知识点上
"连错 3 次"和"还没开始"并列出现。

已按"有没有作答过"分开说：没答过才叫未开始，答过就报"还没答到点上"。
**凡是状态文案，都要先问一句"这句话对当前处境成立吗"。**

### 4.5 `**加粗**` 没渲染

后端生成的文案里有 `**记忆缺口**` 这样的强调标记，原来当纯文本渲染，
界面上就带着两个星号，像没写完的 Markdown。
加了只处理这一种语法的 `InlineText` —— 不引 Markdown 渲染器，
因为内容是后端拼的固定句式，不需要通用解析。

## 六、需要你决定的一件事（不是 UI 问题，但会砸演示）

**核验判定过严：12 个知识点里 10 个被判"存疑"。**

切到 qwen-plus 之后，L2 模型自评比原来的 deepseek-chat 严格得多，
把"原文没有逐字写出、但属于合理展开"的内容也判成可疑。实测样例：

> 知识点「临界资源与临界区」→ `suspect`
> 理由：*原文未提及'临界区本身不具并发安全性'这一表述…
> 原文只说'需申请与释放'，未断言临界区'本身不安全'。*

这是把**"原文没逐字说"当成"可能错了"**。两者的严重程度完全不同。

演示时会显得"整份资料都不可信"，反而砸掉"可信度核验"这个卖点 ——
它本该展示的是"大多数可信、少数有问题"，现在没有信号。

**没有动它**：这属于 P2 的业务行为，你说过"不改业务逻辑"。给你三个选项：

1. **调 Prompt 的判定口径**（最省事）：让模型区分"原文未直接支持"与"与原文冲突"，
   只有后者才算 suspect —— 属于 prompt 微调，不是新逻辑。
2. **换回 deepseek-chat 或换更宽松的模型**：判定口径会跟着变，问题可能自愈。
3. **调整 UI 的呈现**（治标）：把 `unverified` 与 `suspect` 在视觉上拉开，
   让"未做核验"不显得像"有问题"。

我建议 **①**，而且它可以在 UI 不动的前提下独立验证 —— 重新跑一次
`python scripts/load_samples.py --reset` 就能看到分布变化。

## 八、下一步

P6 还差技术方案里列的这些：**全局错误处理 / 加载态 / 空态收口、部署上线、E2E 回归、演示视频**。

另外三件与本次改造直接相关的：

1. **核验口径**（见第六节）—— 建议优先，它影响演示的核心卖点。
2. **加载态**：现在资料解析、索引、Tutor 首轮都有等待，但只有文字提示，
   没有骨架屏。演示时网络慢会显得"卡住了"。
3. **空状态**：学习页的空状态做了（没资料 / 没记录两种），
   资料库与知识地图的空状态还是原来的文字，没统一到新语言。

### 为什么"当前学习焦点"要放在顶层

`src/app/LearningProvider.tsx` 是整个应用里「正在学什么」的**唯一出处**。理由：

知识地图必须和 Tutor 联动（高亮当前节点、点节点跳去学习）。如果各自维护一份状态，
就会出现"Tutor 在学 A、地图高亮 B"这种自相矛盾。放在 Provider 里之后，
两个视图读的是同一份数据，天然一致。

Provider 里还做了**并发保护**：每轮请求带一个自增 id，回来时 id 不是最新的就丢弃结果 ——
避免学习者快速操作时旧响应覆盖新状态。

## 三、界面语言：立成一条纪律

用户的原话是：**「你的界面里出现大量开发者的东西，很不美观，用户看不懂，为什么要显示呢？」**

这句话被立成一条硬规则，落在 `src/features/learn/voice.ts`：

> **凡是用户可见的文字，先过这一层。这一层里不允许出现英文术语、数据库字段名、
> 状态机名字、置信度/相似度。后端字段不许直接拼进 UI。**

### 清掉的东西

| 位置 | 原来显示 | 现在 |
|---|---|---|
| 知识点卡片 | `置信度 95%` | `可信 / 存疑 / 有出入 / 还没核对` |
| 图谱统计 | `图谱概览 / 节点 / 边 / 孤立节点 / 章节层数` | 「我读出了 6 个知识点，找到 3 条关系。还有 1 个暂时没连上。」 |
| 图谱图例 | `节点左边框 = 校验状态` | `左边框颜色 = 这条知识可不可信` |
| 核查层 | `规则校验 / 模型自评 / 联网核验` | `比对原文 / 独立再判断 / 上网查证` |
| 资料元信息 | `7336 字符 · 28 个文本块` | `8 页 · 9 张图片 · 473 KB` |
| 解析警告 | `公式与图表…**P1 暂不支持**`、`第 13/26 批未产出知识点` | `资料里有 9 张图片…讲解时会以文字内容为准。`（内部批次信号直接丢掉） |
| 卡片掌握度 | `掌握度 0.00` | `还没答到点上` |
| 后端生成的回顾语 | `作答 3 次，掌握度 0.00` | 前端从同一批记录重新组织：`连错 3 次，卡在记不牢上` |
| 解析状态 | `解析中 / 切分中 / 抽取中` | `读取中 / 整理中 / 提炼中` |
| 报错 | `HTTP 409`、`fetch failed` | `这一步和之前的状态对不上，刷新一下再试。` |

### 三个关键决定

**1. 回顾语在前端重新组织，而不是复述后端原文。**
后端 `build_recall_note` 生成的是给开发者看的口吻（带「掌握度 0.00」）。
前端拿 `memory.knowledge_state` 里的**同一批真实记录**重新组织句子 ——
事实来自数据库（不会被编造），只是换一种说法。
后端文案不动（那是排障依据）。
> 注意：`stripRecallPrefix` 仍用后端原文精确剥离正文前缀，**剥离要精确匹配，显示才换说法**。

**2. 内部信号直接丢掉，不翻译。**
「第 13/26 批未产出知识点」这类是给我们调抽取参数用的，
它不影响学习者的任何决策，翻译它反而是噪音。所以 `friendlyWarnings` 里直接 `continue`。

**3. 同一个概念全应用只允许一种叫法。**
可信度状态统一引 `VERIFY_STATUS_LABEL`（曾经卡片说"未核对"、图例说"未校验"）；
掌握程度的判断统一走 `pointStatusWords`（列表和详情都引它）。

## 四、动效系统（8 项）

技术选型：**motion v13**（配 Radix Collapsible）。

统一纪律：**位移 ≤ 6px · 时长 ≤ 320ms · ease-out-quart · 禁弹性回弹**。
弹跳/回弹是"泛 AI 装饰"，不是教育软件该有的手感。

| # | 要求 | 实现 |
|---|---|---|
| 1 | 知识点状态变化过渡 | 卡片色/描边走 CSS transition；掌握条走 motion |
| 2 | 掌握度数字/进度过渡 | `AnimatedNumber` 用 rAF 从旧值补间到新值（500ms ease-out）；`ProgressBar` 用 `scaleX`（不触发布局，60fps） |
| 3 | 答对/答错不同反馈 | 答对：轻轻抬起 + 墨绿浮现；答错：**轻晃一次**（±5px，不刺眼）+ 绛色浮现 |
| 4 | 六种动作不同视觉提示 | 各有「符号 + 配色 + 一种微动」：追问 `?` 靛青 / 讲一讲 `—` 墨绿左移入场 / 换个讲法 `↻` 赭色纵向压缩 / 加点难度 `↑` 上移 / 放慢一点 `↓` 下沉坐稳 / 收个尾 `✓` 收拢 |
| 5 | 助教消息渐进出现 | `ProgressiveText` 按**段**依次显影（间隔 45ms），**不是打字机** |
| 6 | 地图与 Tutor 联动 | 当前学习节点画虚线圈；正在学的知识点若属于另一份资料，地图顶部给「切过去看看」 |
| 7 | 页面/回顾卡转场 | 回顾卡用 `Reveal` 浮现；标签页切换保留 DOM 状态（不重放动画） |
| 8 | 减少动效 | `useReducedMotion()` → 所有组件退化成"直接呈现"，信息不丢；CSS 侧由全局 media 查询兜底 |

## 六、视觉验收抓到的三个回归

**这次最大的收获是"逐页截图"这件事本身。** 三个问题都是代码 review 看不出来、
只有渲染出来才显形的：

### 1. 书签卡又出现「还没开始」和「连错 3 次」并存

我在 `voice.ts` 重写 `masteryMark` 时，把上一版的修复弄丢了 ——
它单独实现了"没作答过才叫未开始"，于是掌握度 0 且答过 3 次的知识点被说成"还没开始"。
**修法：让它直接复用 `pointStatusWords`**，一处判断、两处显示天然一致。

### 2. 回顾卡片露出 `**记忆缺口**` 的星号

`InlineText` 只包在助教消息正文上，回顾卡片漏了。
（这个 bug 上一版修过一次，重构时又漏 —— 说明**同类渲染点应该共用组件**，
而不是每处各自记着要包一层。）

### 3. 后端原文里的「掌握度 0.00」直接显示给用户

见第三节决定 1。

### 附：分包时的一个坑

加 `manualChunks` 之后 `vendor-radix` 显示 156KB，看起来像"Radix 很重"。
用 sourcemap 一查，里面装的是 **react + react-dom + scheduler** ——
rollup 会把 react 归到它被引用的那个手动 chunk 里。
给 react 单独一个 chunk 后真相清楚了：**Radix 只有 13.5KB**。

## 八、依赖安装的坑（重要）

**`npm install` 在本项目目录下会静默失败**（无任何输出、退出码 1），
但 `npm view` 可用、在临时目录 `npm install` 也完全正常。
清 `NODE_OPTIONS`/`PYTHONPATH`、换 cache 目录、免沙箱执行**都试过，无效**。

**可行解法：在临时目录装好，再把包 `cp -r` 进项目的 `node_modules`**，
同时手动把包写进 `package.json`。装完必须用 `tsc --noEmit` 验一遍解析。

已装的库：`motion@13.4.0`（含 framer-motion / motion-dom / motion-utils）、
`@radix-ui/react-collapsible`（及其传递依赖）、`clsx`、`tailwind-merge`。
> Select 与 Tooltip 装过但最终没用上（实际只用 Collapsible），已从依赖里移除 ——
> 手写原生 `<select>` 足够，少一层依赖。

## 三、五个交付项

### 3.1 简化遗忘曲线

```
掌握度 < 0.40 → 10 分钟后复习
掌握度 < 0.60 → 1 小时后
掌握度 < 0.75 → 1 天后
掌握度 < 0.85 → 3 天后
掌握度 ≥ 0.85 → 7 天后
答错 → 间隔 × 0.25；连错 ≥ 2 次 → 直接压到 5 分钟
下限 5 分钟（避免"1 秒后再见"这种没意义的调度）
```

**为什么是"简化"的**：真正的遗忘曲线（SM-2 / FSRS）需要每个学习者的大量历史留存数据
去拟合参数。我们现在的作答量远不够回填，硬套一个公式只会得到"看起来精确、实际没有依据"的数字。
这里用的是**可解释的间隔映射**：每一档都能用一句人话解释清楚，也能被测试钉住。
参数集中在 `ReviewCurve` 一个类里，将来数据够了想换成真实曲线，替换这一个类即可。

`next_review_at` 的写入放在 `learner_service.update_learning_state` 里，而不是让调用方
再单独调一次 —— 技术方案本来就把"掌握度增量"和"遗忘曲线"并列在这一步名下，
它们是一件事的两面：**"这次学得怎么样"与"下次什么时候再碰"**。分开写迟早会漏掉一个。

> 这里有个循环导入要绕：`memory_service` 需要 `learner_service.DEFAULT_LEARNER_ID`，
> 反向再导入就会成环。用了函数级导入，代码里写明了原因。

### 3.2 薄弱点聚合

紧迫度不是只看掌握度，三个信号叠加：

```
紧迫度 = (1 - mastery) × 重要度倍率(0.9~1.3) + 连错加成(≥2 次 +0.2) + 到期加成(+0.15)
```

**只纳入作答过的知识点** —— 没学过的不叫薄弱，叫未学。
已掌握的默认排除（它们不该出现在"该加强"的清单里）。
排序带 `knowledge_point_id` 作次级键，保证**结果稳定**：否则紧迫度相同的几条
在两次查询之间可能换序，界面看起来在跳。

### 3.3 首屏"待复习"

`next_review_at <= now` 且作答过的知识点，按过期时间升序。
从没调度过的（`next_review_at` 为空）**不算到期** —— 那是"还没开始学"，归薄弱点清单管。

### 3.4 用户画像（偏好讲法）—— 本阶段最需要想清楚的一项

验收要求「讲解风格与**上次一致**」。这句话决定了整个设计：
**风格必须稳定**，如果每轮都从最近的作答重新推导，它会随最近几次错因来回横跳，
学习者只会觉得"这老师每次讲得都不一样"。

所以：**推导一次、存下来、只在证据足够充分时才切换**。四条规则：

| 规则 | 理由 |
|---|---|
| 手动设定的永不被覆盖 | 用户明确表达过的偏好优先于系统从错因里猜的 |
| 样本 < 3 条时保持现状 | 不因为多错了一次就换风格 |
| 只有某类错因占比 ≥ 60% 才切换 | 错因分散说明没有单一偏好，别硬套 |
| 推导结果与当前相同时只更新证据快照 | 不动风格，避免无意义写入 |

错因 → 讲法的映射（**据"为什么错"决定"怎么讲"**）：

| 错因 | 讲法 | 注入 Prompt 的指令 |
|---|---|---|
| 概念混淆 | `contrast` | 把容易混淆的概念并排对比，指出区别与适用边界 |
| 记忆缺口 | `structured` | 先给可记忆的框架（分类/步骤/口诀），再展开细节 |
| 推理断裂 | `stepwise` | 把中间步骤一步步补全，不要跳步 |
| 看错题意 | `clarify` | 讲解前先澄清"这道题到底在问什么" |
| 样本不足 / 分散 | `balanced` | 用清晰常规的讲法即可 |

指令刻意写成**具体的动作**而不是"请根据学习者画像调整"这种空话。
有测试逐条断言"每个风格的指令都非空、且各不相同、且不含空话"。

### 3.5 掌握度看板

一个接口返回首屏要的全部东西：概览（已掌握/学习中/薄弱/未学）+ 待复习 + 薄弱点 + 画像 + 复习曲线参数。

## 五、Runtime 扩展

状态机插了一个状态，放在 `LOAD_STATE` 之后、`RETRIEVE` 之前：

```
LOAD_STATE → LOAD_MEMORY → RETRIEVE → DECIDE_ACTION → EXECUTE_ACTION → WAIT_USER
```

放在 RETRIEVE 之前是因为**讲法偏好要跟着后面的决策与内容生成一路传下去**。

`LOAD_MEMORY` 做三件事：取/刷新画像、取该知识点的复习状态、取跨知识点的薄弱点。
**读不到记忆也照常教学**（`load_memory` 内部保证不抛）—— 长期记忆是增强项，
不该成为"能不能开始学习"的前置条件。

### 主动回顾：验收的核心

新会话首轮，如果这个知识点有历史且曾经卡住过，把回顾语放在教学内容之前：

```
你上次学过这个知识点，作答 3 次，掌握度 0.00。结束时连续答错 3 次，卡在**记忆缺口**上。
按复习计划，这个知识点现在正好该回顾了。我们先把上次没通的地方捡起来，再往下走。
```

三个刻意的设计：

1. **只在新会话首轮**。后续轮次学习者刚做完题、注意力在当下，每轮都提"上次"会变成噪音。
2. **提示语是拼出来的，不是模型自由发挥**。验收要求"能**主动提到**上次的薄弱点"——
   主动的前提是这句话必须来自真实记录。模型可以润色教学内容，但"上次错在哪"不该由它编。
3. **同时落进 messages 表**，事后能查到"当时系统确实提过这件事"。

### 几处值得一提的测试取舍

- **`LOAD_MEMORY` 出现在轨迹里**，且断言排在 `RETRIEVE` **之前** —— 顺序是有意义的，

## 九、本阶段修掉的问题

### 问题 1：测试读到真实实验数据，断言飘了

`error_type_counts` 是**按 learner 全局汇总**的（这正是设计意图 —— 画像必须跨会话），
而测试用了共享的默认学习者，于是读到了我历次实验留下的真实记录
（concept_confusion 6 条、misread 1 条、reasoning_break 6 条），
导致"错因占 46%、没有明显偏好"的判定，画像测试全挂。

**不是代码缺陷，是测试隔离问题。** 修法是让每个夹具用独立的 `learner_id`
（`test-mem-xxxxxxxx` / `test-p5-xxxxxxxx` / `test-api-xxxxxxxx`）——
既保证隔离，又**不动真实数据**（另一条路是清空默认学习者的记录，那会毁掉真实数据）。

### 问题 2：推导依据用了英文错因码，而它是给用户看的

`style_evidence._note` 原本是 `错因以 concept_confusion 为主（3/3）`。
这段文字会出现在接口返回里、被前端展示给用户。已改为
`错因以「概念混淆」为主（3/3 次）`。

### 问题 3：同一个错因在两处两个叫法

后端 `ERROR_LABEL` 写"记不牢"、前端 `ERROR_TYPE_LABEL` 写"记忆缺口"，
用户会以为是两回事。已统一为：概念混淆 / 记忆缺口 / 推理断裂 / 看错题意。

跨语言没法用测试钉住，所以在**两个文件里都写了注释指向对方**，提醒改一处要同时改另一处。

### 顺带：一处纯函数被拆掉了

`memory_service` 里的 `_recreate` 系辅助没有独立测试价值，直接做成纯函数 + 表驱动，
测试覆盖的是"每一档间隔的具体数值"而不是"函数被调用了"。

## 十一、已知限制

| # | 限制 | 说明 |
|---|---|---|
| 1 | **未做多轮对话记忆压缩**（P4 遗留） | `messages` 全量保留，但喂给 Prompt 的只有当前轮的资料与状态。长会话（20+ 轮）后模型看不到早期问答细节 |
| 2 | 遗忘曲线是固定的间隔表，不随个体调整 | 每个学习者的真实遗忘速度不同，当前所有人的曲线一样。要做个体化需要更多历史数据 |
| 3 | 画像只从错因推导，不看偏好信号 | 例如"学习者主动要求举例"这种正反馈没有被纳入。当前只有负向证据 |
| 4 | 薄弱点只看单知识点，没做前置关系传播 | 某个知识点薄弱时，它依赖的前置知识点其实也该复习。`knowledge_relations` 里有 `prerequisite` 关系可用，但本阶段没做 |
| 5 | 前端讲法下拉是全局的 | 所有知识点共用一个讲法偏好，不支持"这门课用对比式、那门课用分步式" |
| 6 | 看板未分页 | 薄弱点/待复习各取前 20 条。知识点多了以后需要分页或筛选 |
| 7 | DeepSeek 余额不足，本阶段全在 mock 下开发（P3/P4 遗留环境问题） | mock 的教学内容由固定模板生成，界面上的教学正文不具参考性；**决策与状态逻辑不受影响**（它们由 Policy 与数据库决定） |

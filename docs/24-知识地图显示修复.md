# 知识地图显示修复

> 日期：2026-09-20
> 用户反馈：知识图谱显示做的有问题，显示太窄了

---

## 〇、先说结论：**"太窄"的真身不是画布窄，是图被缩放压小了**

我一开始也以为是容器不够宽，量完才发现真正的问题：

| | 修复前 | 修复后 |
|---|---|---|
| 图自然宽度（108 知识点那份） | **958px** | **590px** |
| 画布 | 646px | 646px |
| **实际缩放** | **0.61×** | **0.98×** |
| 11.5px 的节点标题实际大小 | **7px（糊）** | **11px（可读）** |

**根因**：布局里 `MAX_PER_ROW = 5` 是写死的，一行 5 个节点就是 958px 宽 ——
比画布宽出 300px，于是适配逻辑把整张图缩到 0.61 倍塞进去。
**缩放把字压糊了，看起来就像"图太窄"**（其实是"图太宽、被压扁"）。

所以修的是**让布局跟着画布宽度走**，而不是单纯去加大容器。

---

## 一、四处修复（按影响从大到小）

### 1. 布局按画布宽度决定每行几个 ★ 主因

`layoutGraph(nodes, { maxWidth })` —— 每行节点数由可用宽度算出：

```
perRow = clamp(floor((maxWidth - 2×PADDING + GAP_X) / (NODE_WIDTH + GAP_X)), 1, 5)
```

- 646px 画布 → 每行 3 个 → 图宽 590px → **缩放 0.98，字是正常大小** ✓
- 画布变宽 → 每行自动变多，仍然铺满
- 仍保留 5 个的上限：一屏 40 个节点不该摊成一条超宽长条

**取舍**：图变窄会变高，超出的行靠上下拖拽看。
**"全都塞进去但看不清"比"看清当前部分、其余拖一下"更没用** —— 尤其这是给学生看的地图。

### 2. 高度不该由邻居内容决定 ★ 藏得很深的 bug

量高度时发现：知识地图的**画布高度一直是被左侧栏内容撑出来的**。

侧栏一收起，画布高度立刻从 478px 塌成 **150px**。
反过来说，**侧栏内容少的时候图本来就矮** —— 只是没人往那个方向想过。

根因：`Shell` 的内容容器是个普通 block div，没有高度，
图谱根节点的 `flex-1` 无从生效。

修法：`Shell` 的内容容器改成 `min-h-full flex flex-col`
（给"工作台型"页面一个明确的高度基准；`min-h-full` 是最小值，普通阅读页照常滚动）。

### 3. 侧栏可收起（画布 646 → 911px）

知识地图是**工作台**，不是阅读栏。侧栏常驻 300px，
在 1262px 的屏上等于把画布砍掉三分之一，而地图恰恰最吃横向空间。

现在侧栏顶部有「收起 ›」，收起后留一个「‹ 设置」能随时展开。
实测：画布 646 → **911px（+41%）**，缩放自动适应到 1.27×。

### 4. 地图不再受 1240px 阅读栏宽度限制

`--size-content-max: 1240px` 对阅读页是对的（那是让人读得下去的行宽上限），
但地图没有"行宽"这回事 —— 多出来的宽度直接变成能看见的更多节点。
现在只有非地图页面套这个上限。

### 新增的 6 条测试

布局是纯函数，所以能直接测。重点守两件事：

- **布局不会宽过画布**（否则又会被缩放压小 —— 这条正是这次事故的回归测试）
- **极窄画布时每行至少 1 个**（向下取整可能算出 0，那会导致死循环或整批节点消失）

另外还测了"画布越窄图越窄""上限仍生效""同行节点不重叠"。

## 四、顺带修掉的一个"看起来像 bug 其实不是"

第一次看截图我以为「SAMPLE ANSWER」分带标着 1 个知识点却没渲染节点。
查 DOM 后确认 **6 个节点全在**，只是那时整张图被缩到 0.61 倍、
白底浅边在截图里几乎看不见。

**这次"误判"本身就是缩放过小的证据** —— 连我都看不清了。

## 五、如果还是觉得不够宽

当前在 1262px 屏幕上，展开侧栏时画布 646px（收起 911px）。
还能再往下走的方向有两个，都需要你拍板（都是更大的改动）：

1. **默认收起侧栏**（已经选好资料时）—— 回到地图多半是为了看图，不是为了再选一次
2. **把侧栏改成顶部工具条** —— 画布能拿到完整的 976px，但"图例"和"这份资料"要重新安排位置

说一声就做。

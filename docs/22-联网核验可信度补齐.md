## 〇、先说最重要的发现：**代码是齐的，缺的是一个 Key**

我原本以为要写不少代码。查完发现——**什么都不缺，只缺配置**：

| 组件 | 状态 |
|---|---|
| L1 规则校验 → L2 模型自评 → L3 联网核验 | **已完整实现**（`verify_service.py`，806 行） |
| Tavily 搜索客户端（含错误码体系 / 超时 / 重试语义） | **已实现**（`tavily_client.py`，249 行） |
| `/api/verify/capabilities` 能力自检接口 | **已实现** |
| 实际生效 | **否** —— `tavily_configured: false`，L3 整层记 `skipped` |

设计上本来就写了：「未配置 Key 时 L3 整层记 skipped 并说明原因，L1/L2 照常跑 ——
**这不是故障，是设计上的降级**」。

所以这次真正的工作是**两件别的事**：

1. **把"没有 Key"这件事变得不可能被忽略**（启动日志 + 配置注释 + 界面不再假装有可信度）
2. **补上从"核查结论"到"助教说的话"之间那段缺失的翻译** —— 这是真正缺的一块

## 一、真正缺的一环：结论 → 人话

### 之前的状态

助教生成教学内容时拿到的上下文只有：知识点、学习状态、上次评估、**RAG 检索片段**、讲法偏好。

**核查结论一个字都没进去。** 也就是说：`knowledge_checks` 表里躺着一堆
`verdict=suspicious` 之类的判断，但助教完全不知道。

### 新增 `app/services/verify_voice.py`

把核查记录翻成助教能直接用在话里的说明。**核心不是"生成一段话"，是"收束"** ——
决定**要不要说、能说什么**。

两条不可让步的不变量（各有一条对应测试）：

#### ① 没联网就不许说查过

未配置 Key 时 L3 是 `skipped`。这时候如果助教说出「我上网查了一下，和你的资料一致」——**那是编的**。

所以输出里带 `may_claim_web` 开关，**没有真正跑过联网核验时它是 `False`**：

```
【关于核查】本次没有联网核验能力。**不要出现「我上网查过」「网上资料显示」
「外部信息表明」这类表述。**你的依据只有学习者的资料本身 —— 如果他的资料没讲到，
就直说「这部分不在你的资料里」，不要用外部知识冒充已核实的结论。
```

光说"不要编造"对模型约束力不够，所以**把禁止的说法点名列出来**。

⚠️ 注意一个容易写错的边界：**历史上有过联网结论、但当前能力已关闭**时，
仍然不许声称。拿过期结论当现在的能力用，同样是在说谎。

#### ② 没什么可说的时候必须沉默

绝大多数知识点是干净的（L1 通过、L2 没报警、L3 也一致）。
这种情况返回**空串**，助教正常讲课。

这是整套设计里最容易写错的地方：把"通过"也当成一条值得汇报的结论，
结果每轮都来一句"已核实"——**学习者很快就会学会无视它**。
所以「沉默是默认值，开口要有理由」。

#### 有信号时说什么

| 情况 | 助教被告知 |
|---|---|
| 外部资料与他的资料有出入 | 如实说明出入，并**明确以他的资料为准**（他要考的是自己的课） |
| 外部也找不到一致依据 | 说明这点，提醒这是「资料里的说法」而非「普遍共识」 |
| 联网执行**失败** | 说"没查到"，**不要暗示已经查过**（失败 ≠ 没有问题） |
| 模型层有保留意见 | 带上具体理由，并说明"如果这条是当前重点就谨慎些，否则不必主动提" |
| 原文支撑不足 | 讲解时说明这是**推导**而不是原文原话 |

每一种都附了同一句收束：

> **这些只是给你自己把握分寸用的，不要照着念，也不要在每轮里都提。**

条件是「学习者问起准不准 / 对不对 / 有没有依据」，或者这个出入正好会影响他当前这道题。

## 二、界面：可信度撤出主阅读流

你选了「只在助教的话里体现」，所以：

**知识点卡片上的可信度标签已移除**（原来的「可信 / 存疑 / 还没核对」色点 + 文字）。理由：

1. **绝大多数是"还没核对"** —— 没跑过校验的知识点占多数，一排灰标签除了制造噪音不传递信息
2. **它把判断变成了一枚徽章** —— 学习者看到「可信」就信了，但那是系统给出的**倾向**，
   不是一句可以照着信的结论

数据照旧留在 `knowledge_checks` 表里（纯后台留痕），由助教在对话里自然带出。

### ⚠️ 有一处我**保留**了，需要你确认

**知识图谱里的节点配色与图例**没有动。理由：

- 它在右侧面板里，不是主阅读流，本来就不"明显"
- 节点颜色是那张图的**视觉语法**。只删图例会导致"有颜色但没人知道什么意思"——
  那是比"显示了可信度"更糟的状态

如果你希望连这处也去掉，说一声我改（要么同步去掉颜色和图例，要么整块保留）。

## 三、配置：你要做的就是填一个 Key

`.env` 与 `.env.example` 都加了说明性注释：

```bash
# 【要启用联网核验，只需要填这一个】
# 去 https://app.tavily.com 注册（有免费额度）拿到 key，填在下面。
# ⚠️ 不填的时候，助教被明确禁止说「我上网查过」这类话，不会拿外部知识冒充已核实的结论。
TAVILY_API_KEY=
```

启动日志现在会明说这件事（已实测）：

```
WARNING | app.main | 联网核验：未生效（未配置 TAVILY_API_KEY）——
                    L3 整层记 skipped，助教不会声称查过外部资料。
```

**为什么这条日志很重要**：没有它的话，演示时看到助教说「这部分不在你的资料里」，
很容易被误判成"模型能力不行"，而实际上是这一层根本没配 Key。

### 新增测试守的是什么

大部分用例断言的**不是"输出了什么"，而是"没输出什么"**：

- 无 Key 时禁止声称查过（且禁止的说法要逐条点名）
- 有 Key 但能力已关时**仍然**禁止
- 三层全过 → 沉默
- `skipped` → 沉默
- 有信号时，必须同时附上「不要照着念 / 不要每轮都提」
- 同一层有多条记录时取**最后一次**（校验是事件流，重跑会覆盖结论）

## 六、你需要做的一件事

**想真正启用联网核验，只需要：**

1. 去 https://app.tavily.com 注册（有免费额度）
2. 把 key 填进项目根 `.env` 的 `TAVILY_API_KEY=`
3. 重启后端

重启后启动日志会变成 `联网核验：已启用（Tavily）`，之后：
- 上传资料时的 L3 层会开始真正联网核验
- 助教在被问到"这个准不准"时，能说"我查过，跟你资料一致"或"网上说法有出入，我按你的资料讲"

**不填也不会坏** —— L1/L2 照常跑，助教只是不会声称查过外部资料。这是刻意的设计：
**宁可不说，不能说假话。**

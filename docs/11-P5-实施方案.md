## 一、技术方案给 P5 定义了什么

原文（`docs/01` 阶段 5）：

> **目标**：跨会话记得住。
> **做什么**：`update_learning_state` 掌握度增量策略 + 简化遗忘曲线；
> 薄弱点聚合；首屏"待复习"；用户画像（偏好讲法）注入 prompt；掌握度看板与薄弱点清单。
> **验收**：关闭浏览器重开会话，Tutor 能主动提到上次的薄弱点并优先复习，讲解风格与上次一致。

所以 P5 就是四层能力里的 **Memory** 那一层 —— P4 把"一轮教学"跑通了，
P5 要让它"记得住上一轮"。验收标准给得非常具体，可以直接翻译成测试。

## 三、五个交付项的设计

### 3.1 简化遗忘曲线

不做完整的 SM-2 / FSRS —— 技术方案写的是"简化"，而且我们没有足够的作答量去拟合参数。
采用**基于掌握度的间隔映射 + 结果修正**：

```
基础间隔 = f(mastery)                    # 掌握得越牢，下次看得越晚
    mastery < 0.40 → 10 分钟
    mastery < 0.60 → 1 小时
    mastery < 0.75 → 1 天
    mastery < 0.85 → 3 天
    mastery ≥ 0.85 → 7 天

答错 → 间隔 × 0.25（且不低于 5 分钟）    # 错了就要尽快再见
连错 ≥ 2 → 间隔固定为 5 分钟            # 明显没懂，别再拖
答对 → 间隔 × 1.0（按上表）
```

`next_review_at = now + 间隔`。纯函数，可测，参数集中在一处。

**为什么不用真实遗忘曲线**：那条曲线需要每个学习者的历史留存数据来拟合，
我们现在每次作答的数据量还不够回填。用一个**可解释的间隔表**更诚实 ——
既能表达"越熟看得越晚、错了马上再看"，又不会假装有统计依据。

### 3.2 薄弱点聚合

"薄弱"不该只等于 `status == 'weak'`。聚合成一个**按紧迫度排序**的清单：

```
紧迫度 = (1 - mastery) * 重要度权重 + 连错加成 + 到期加成
  - 重要度：knowledge_points.importance（1~5）归一化
  - 连错加成：consecutive_wrong >= 2 时 +0.2
  - 到期加成：next_review_at 已过期时 +0.15
```

只纳入"有过作答"的知识点（`attempt_count > 0`）—— 没学过的不叫薄弱，叫未学。

### 3.3 首屏"待复习"

`next_review_at <= now` 且 `attempt_count > 0` 的知识点，按过期时间升序。
这就是"该看了"的队列。

### 3.4 用户画像（偏好讲法）

**这是最需要想清楚的一项。** 验收要求"讲解风格与上次一致" —— 也就是说风格必须**稳定**，
不能每轮重新推导、来回横跳。

设计：

```
从 answer_evaluations 的错因分布推导初始风格：
    concept_confusion 占多  → "contrast"   对比式：把易混概念并排讲
    memory_gap 占多         → "structured" 结构化：给可记忆的框架/口诀
    reasoning_break 占多    → "stepwise"   分步式：把推导链补全
    misread 占多            → "clarify"    审题式：先澄清问题在问什么
    样本不足（< 3 条）       → "balanced"   均衡

稳定性规则（关键）：
    - 已有风格且证据不足（新错因样本 < 3 条）→ **保持不变**
    - 只有当"某一种错因明显占优"（占比 ≥ 60% 且样本 ≥ 3）时才切换
    - 用户手动设定过的（style_source = "manual"）→ 永不自动覆盖
```

存 `learner_profiles` 表：`learner_id` / `preferred_style` / `style_source`(derived|manual) /
`style_evidence`(JSON，各错因计数) / `stats`(JSON) / `updated_at`。

注入 Prompt 时给一句**具体的讲法指令**，而不是"请根据画像调整"这种空话：

> 这位学习者的主要困难是概念混淆，讲解时优先把容易混淆的概念并排对比，
> 明确指出它们的边界在哪里。

### 3.5 掌握度看板

一个接口返回首屏要的全部东西：
整体掌握度概览（已学/已掌握/薄弱/未学计数）+ 薄弱点清单 + 待复习清单 + 画像摘要。

## 五、Runtime 扩展

状态机加一个状态，放在 `LOAD_STATE` 之后、`RETRIEVE` 之前：

```
LOAD_STATE → LOAD_MEMORY → RETRIEVE → DECIDE_ACTION → EXECUTE_ACTION → WAIT_USER
```

`LOAD_MEMORY` 做三件事：

1. 取/刷新该学习者的画像；
2. 取该知识点的复习状态（是否到期、上次错因）；
3. 取全局薄弱点（用于跨知识点的"上次你在这方面吃过亏"提示）。

**新会话首轮**：如果这个知识点有历史（`attempt_count > 0`）且有薄弱记录，
在教学内容前加一段**回顾提示**，并把细节写进 `TurnResult.memory`：

```
上次你在这里连续答错了 2 次，错因是概念混淆，我们先把这个点捡回来。
```

这段提示是**由数据驱动的**，不是模型自由发挥 —— 验收要的正是"主动提到上次的薄弱点"。
有专门的测试断言：第二个会话的首轮必须提到第一个会话留下的薄弱点。

同时 `tutor_decision` 与 `tutor_actions` 的 Prompt 里注入讲法偏好指令。

## 八、验收标准对齐

技术方案的验收是「关闭浏览器重开会话，Tutor 能主动提到上次的薄弱点并优先复习，讲解风格与上次一致」。
拆成三条可测的断言：

| 验收点 | 怎么测 |
|---|---|
| 主动提到上次的薄弱点 | 会话一在同一知识点连错 2 次 → 会话二首轮 `memory.mentioned` 为真且正文含薄弱点描述 |
| 优先复习 | 会话二首轮的决策上下文里带上"到期待复习"信号；且 `next_review_at` 已让我方判定为到期 |
| 讲解风格与上次一致 | 会话一建立的 `preferred_style` 在会话二被读回并注入 Prompt，且两次注入的指令字符串一致 |

前两条在 `test_runtime_memory.py`，第三条同时断言 Prompt 内容与返回值。

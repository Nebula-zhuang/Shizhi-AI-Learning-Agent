### 4.2 LLM 调用（真实 DeepSeek）—— ✅ 成功

**非流式 `POST /api/chat`**

```
HTTP 200 | 耗时 2217 ms | model=deepseek-chat | mode=live
```

提问「用两句话解释什么是梯度下降，并举一个生活中的类比」，实际回答：

> 梯度下降是一种优化算法，通过沿着函数梯度的反方向逐步调整参数，使目标函数值不断减小，
> 最终逼近最小值。生活中的类比：下山时，你每次都朝着脚下最陡的下坡方向迈一小步，
> 最终到达山谷底部。

回答准确、类比恰当 —— 真实模型调用成立。

## 六、本轮修复的 4 个真实问题

| # | 问题 | 根因 | 修法 |
|---|---|---|---|
| 1 | **循环导入**：脚本中先 `from app.models.app_meta import Xxx` 会抛 `ImportError: partially initialized module` | `db/base.py` 既是 Base 定义处、又在文件尾部反向导入模型，形成环 | 拆出 `db/base_class.py` 只放 Base；`db/base.py` 作聚合入口；模型一律继承 base_class。三种导入顺序均已实测通过 |
| 2 | Alembic 启动即崩（`UnicodeDecodeError: 'gbk' codec`） | Alembic 用 `encoding="locale"` 读 `alembic.ini`，中文 Windows 上是 GBK | 该文件改为纯 ASCII 并在文件头注明 |
| 3 | `.env` 中 `CHROMA_PERSIST_DIR=` 留空会冲掉默认路径 | 空字符串覆盖字段默认值 | 加 `field_validator` 空值兜底 |
| 4 | 日志脱敏串不反映 `DATABASE_URL` 覆盖 | 脱敏属性写死了 MySQL 分项拼接 | 改为对实际生效 URI 做口令替换 |

其中 **#1 是只有在数据库连通后才暴露出来的**——此前 MySQL 连不上，
冒烟脚本执行不到那段代码，问题被掩盖了。这也说明「部分可用」的验证容易留下盲区。

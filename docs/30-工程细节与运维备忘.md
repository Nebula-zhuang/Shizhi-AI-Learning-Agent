## 二、`RAG_MAX_DISTANCE` 的校准依据

**`0.40` 是实测校准值，不是拍脑袋定的。**

用 `text-embedding-v3` 在两份语料（9 块的讲义、120 块的真实论文）上测距：

| | 最近距离区间 |
|---|---|
| 资料内问题 | 0.145 ~ 0.286 |
| 资料外问题 | 0.415 ~ 0.577 |

可用区间 0.42~0.48，取 0.40 偏向召回。

**换 embedding 模型后必须重新校准**：

```bash
python scripts/calibrate_rag.py --document-id <资料id> --auto-questions
```

脚本会打印两类问题的真实距离分布并给出建议门槛。

**换向量模型时必须同时改 `EMBEDDING_DIM` 并重建索引。**
维度写错会在索引时明确报 `dim_mismatch`，不会静默写入错维度的向量。
集合会记录**向量化指纹**（`provider:model:dim`）而不只是维度 ——
维度相同不代表语义空间相同，换模型后混杂了也不报错。

## 三、几个设计决策的来龙去脉

这些是"为什么这么做"，写在 README 里太占篇幅，但改代码前值得一看。

### 3.1 Agent Loop 为什么与 Tutor 状态机并存，而不是合并

Tutor 的 `runtime.py` 是九态**线性**流水线，其中 `DECIDE_ACTION` **一轮只执行一次** ——
这是刻意设计（"每轮只能选一个主教学动作"是硬约束），不是没写完。

而自由学习需要"看完工具结果再决定要不要继续"。
把两种模型塞进同一个状态机会让**教学策略**和**工具编排**互相牵制 ——
下次改教学阈值时得先想清楚会不会影响工具循环，反之亦然。

两者共用的只有底层的 `ToolRunner` / `ToolBudget`。`runtime.py` 在阶段 2 一行未改。

### 3.2 `LOOP_TIMEOUT_S` 为什么不约束最终生成

**生成就是降级目标本身。** 给生成也设时限，超时后就什么都不能输出了 ——
那正好违背"无论如何都要给用户一个回复"这条原则。

代价要说清楚：**用户实际等待 = 编排耗时（≤30s）+ 生成耗时**。
实测一个"检索 → 判断 → 联网 → 判断"的完整回合约 30s
（其中编排约 26s、生成约 4s）。所以 30s 应理解为
"愿意在**工具编排**上花多久"，而不是"整轮最多 30 秒"。

### 3.3 为什么"联网能力配置错误"不允许回退

MCP **连不上 / 401 / 超时** → 可以回退 Tavily（网络抖一下而已）。

MCP **连上了但能力清单里没有搜索工具** → **不回退**。

后者是**配置/兼容性错误**，不是网络问题。静默回退会把"工具名对不上"
这种确定性错误永远掩盖成"网络偶尔不好" —— 你会一直以为 MCP 在工作，
直到某天备用通道也不可用。

现实中真发生过：Tavily MCP 的官方文档写 `tavily-search`，
而 `tools/list` 实际返回 `tavily_search`。**差一个字符，功能全废。**

### 3.4 Time Tool 为什么要"预注入"而不是"让模型自己调"

实测：用户问「今天几号」，模型靠记忆答了 **2024 年 6 月 13 日**
（实际 2026-09-20，差了两年多）。这类错误的可怕之处是**答得非常自信** ——
用户没有理由怀疑，除非他自己知道今天几号（那他就不会问了）。

只做"识别 + 进循环"是**不够的** —— 那仍然**指望模型主动去调**时钟工具，
而实测它就是不调。

所以识别到时钟信号时，**在进循环之前就把真实时间放进观察里**。
这样模型看到的素材里就有正确日期，**想答错都难**。

这是"**不依赖模型自觉**"的思路 —— 与"硬限制写在代码里"是同一条原则。

**为什么是本地工具而不是联网查**：本机时钟权威、免费、瞬时；
联网查日期反而引入延迟和不可靠来源。所以 `current_time` 是 `counted=False` ——
本地读，不占"最多 3 次外部调用"的额度。

### 3.5 视觉为什么用单独的模型

图只在"用户真的传了"时出现。让每一轮纯文本对话都付 VL 模型的价钱不划算。

`vision_gateway()` 与项目里已有的 `llm_model_fast` 是**同一个模式**：
不新建连接池配置，只把 `llm_model` 换掉，超时/密钥/base_url 全部继承。

**为什么 `LLM_SUPPORTS_VISION` 默认 false 且必须显式声明**：
不支持视觉的模型**接口不报错**，只回一句"我看不到图"，
工具于是返回 `ok=True` 的废结果，Agent 还会白转好几轮。
**不能靠"发过去看行不行"。**

### 3.6 对话附件为什么复用 `documents` 表

一个用户上传的图片**就是一份资料** —— 它该出现在"书房"里、也该能被检索。
另建 `attachments` 表会让同一份文件在两处出现，
然后"删了对话里的图、书房里还在"这类不一致就会冒出来。

摄取也复用同一条流水线：一份文件不管从书房传还是从对话里传，
都该落到同一个地方、走同一条处理链。两套实现迟早会在
"去重规则 / 大小限制 / 格式判定"上分叉。

**看图不需要等摄取完成** —— `storage_path` 在落盘那一刻就有了，
摄取只是让它同时也进书房、进检索。

### 3.7 模型不支持视觉时，为什么工具要"不出现在清单里"

让模型看见一个注定失败的工具，只会浪费它一次决策。
所以 `available_specs()` 与 `names()` 刻意分开：
前者只列**当下真的能用**的，后者列全部注册过的。

### 3.8 结构化工具调用为什么不用原生 function calling

原生 function calling 各家支持程度不一，且会多一轮往返。
项目统一走自己的 JSON 通道 —— 与 P1/P2/P4 一致，改动面为零。

**这是一个可回退的决定**：若后续实测发现模型工具选择质量不足，
可以把它作为独立阶段引入，不需要动 Agent Loop 的结构（见「工程债」）。

## 四、故障排查

| 现象 | 原因与处理 |
|---|---|
| 界面显示 `LLM 网关: mock` | 未配置 `LLM_API_KEY`。填好后重启后端 |
| `MySQL` 徽标为黄色 | 数据库连不上。检查服务是否启动、`.env` 里口令是否正确 |
| 启动报 `Access denied for user` | 口令错误。MySQL 8+ 默认 `caching_sha2_password`，已依赖 `cryptography` 包支持 |
| RAG 接口返回 **409** | 未配置 `EMBEDDING_API_KEY`。这是**刻意的** —— 不静默降级成假向量 |
| 回答一次性全部出现、没有逐字效果 | 代理缓冲了 SSE。开发期走 Vite 代理；Nginx 部署需关 `proxy_buffering` |
| 联网引用显示「备用通道」 | MCP 运行时故障，已自动回退 Tavily。看 `fallback_reason` 定位 |
| 联网直接明确失败（无回退） | `mcp` 模式下的预期行为；或 MCP 能力清单里没有搜索工具（配置错误） |
| 问"今天几号"答错年份 | 不应发生。若发生，检查时钟信号是否命中、预注入是否执行 |
| 传图后回答"看不到图" | 未配置 `LLM_VISION_MODEL` 或 `LLM_SUPPORTS_VISION=false` |
| `alembic.ini` 报编码错误 | 该文件**必须保持纯 ASCII**（Alembic 按 GBK 读取） |
| `data/chroma` 报 `attempt to write a readonly database` | 两个进程同时访问同一个 Chroma 目录（SQLite 不支持多进程写）。见下节 |

### ⚠️ `data/chroma` 只支持单写者

SQLite 后端不支持多进程并发写。**两个进程同时访问同一目录会让检索间歇性失败**，
且报错（`attempt to write a readonly database`）很难联想到并发问题。

部署时请保证单写者。

## 五、安全约定

- **凭据只允许写入项目根 `.env`**（已 gitignore）。
  **禁止**出现在源码、README、验收报告、日志、测试文件中
- 汇报与截图时**一律脱敏**（如 `sk-***47`）
- 涉及凭据的改动后，请复跑 `python scripts/scan_secrets.py`
- 自由学习的对话与附件**要求登录**；P1–P6 的接口保持原有的"未登录可用"行为
- `.env` 的所有变体（`.env.local` / `.env.production` …）均不入库，只保留 `.env.example`

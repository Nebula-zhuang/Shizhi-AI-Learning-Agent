## 一、docx：不是"现在不接受"，是**从来没接受过**

### 根因

```python
# app/ingestion/base.py
SUPPORTED_EXTENSIONS = {
    ".pdf": "pdf",
    ".txt": "text", ".md": "text", ".markdown": "text",
    ".png": "image", ".jpg": "image", ".jpeg": "image", ".webp": "image",
}   # ← 没有 .docx
```

而前端 `accept` 里放了 `.docx`，界面文案还写着"支持 Word"。

**文案跑在了能力前面。** 用户能选中 .docx，传上去才被告知"不支持的文件类型「.docx」"——
这是最糟的一种交互：**先答应，再反悔。**

我上一轮做上传扩容时还给这段文案加过"支持 PDF、Word、Markdown…"，
**当时没有核对后端到底支不支持** —— 是我的疏忽。

### 修法：真的把它做出来

技术方案里本来就规划了 `python-docx`，所以正确做法不是把前端那行删掉，而是补上能力。

**新增 `app/ingestion/docx_parser.py`**（约 280 行）：

| 能力 | 实现要点 |
|---|---|
| 标题层级 | 映射 Word 样式名 → 1–9 级。**必须同时覆盖中英文**：中文版 Word 存 `标题 1`，英文版存 `Heading 1`，同一份文档换个语言环境另存就变了 |
| 正文 | **不用 `paragraph.text`** —— 它漏掉超链接里的文本。学术资料里"参见第 3 章"这类引用常是超链接，丢了上下文就断了。走 XML 取全部 `w:t` |
| 表格 | 转成 Markdown 管道格式（不是制表符）。块内容后面要过模型抽取，管道格式边界清晰得多 |
| 内嵌图片 | 从 `r:embed` 关系取二进制并落盘，图片本身成为独立的 `figure` 块 |
| 分页 | docx **没有物理页码**（页由渲染器决定，文件里没存）。走虚拟分页，并在 warnings 里**明说这件事** —— 不能让用户把虚拟页号当成真实页码 |
| 正文顺序 | **遍历 `body.iterchildren()` 而不是分别遍历 `paragraphs` / `tables`** —— 后者会丢掉交错顺序，让"表 3-1"和讲它的那段话脱节 |

### 一个写错了又修掉的细节

第一版把图片"挂到邻近的文字块上"，结果**遇到"只有图片、没有文字的段落"时下标越界，图片全丢**。

改成**让图片自己成为一个 `figure` 块**（`BlockType.FIGURE` 本来就是为此存在的，PDF 路径也是这么做的）——
既修掉了错误，语义也更对：图本来就是一个独立的内容单元。

### 顺手补的：旧格式的针对性提示

`.doc` 是 Word 97-2003 的二进制格式，和 `.docx`（zip + XML）完全是两种东西，`python-docx` 读不了。

与其让它落到"不支持的文件类型"那句毫无信息量的提示里，不如**明确告诉用户怎么办** ——
这类用户往往并不知道自己存的是旧格式：

```
上传 .doc   → 「这是 Word 97-2003 的旧格式（.doc），和 .docx 是两种不同的文件。
                 请用 Word 打开后「另存为」.docx 再上传。」
上传 .pptx  → 「暂不支持演示文稿。如果内容重要，可以导出为 PDF 再上传。」
```

覆盖 `.doc` / `.wps` / `.ppt` / `.pptx` / `.xlsx` / `.epub`。

## 二、书架删除

### 之前的情况

删除功能**其实存在**，但只藏在"点开某份资料 → 详情区标题栏"里。
书架上每张卡片**没有任何删除入口** —— 用户扫一眼书架，确实会觉得"只有上传"。

### 现在

每张书脊卡右上角有一个删除图标：

- **常驻但不抢眼** —— 藏在 hover 里的话触屏和键盘用户根本找不到；
  做成醒目的红色按钮又会让整面书架像危险操作面板。
  所以是个默认很淡的图标，**悬停才变警示色**。
- **正在解析的禁用**，并给出 tooltip「正在处理中，稍后可以删除」。
  后端本来就会拒（409），但**按钮直接禁用比点了才报错好**。
- 点击后弹确认层，文案把"会一起删掉什么"说清楚：

```
删掉这份资料？
「操作系统原理-第3章.pdf」以及从它读出的 6 个知识点、相关的关系与索引都会一起清掉。

这个操作不能撤销。之后再想看，需要重新上传一次，也要重新花时间读一遍 ——
如果只是想重新解析，用「重新读这份」就够了。

                              [先留着]  [确认删除]
```

**为什么用弹层而不是"点了就删 + 撤销提示"**：这个产品里一份资料背后是
**几十次模型调用换来的知识点**，误删的代价比多一次点击高得多。
文案里也顺带指了条明路（想重新解析用「重新读这份」，不必删）。

详情区原有的删除按钮也统一走同一个确认层 —— **不给同一个动作留两种行为**。

## 五、需要你知道的

1. **`.doc` 仍然不支持，而且短期内不会支持** —— 那是完全不同的二进制格式，
   需要另一套解析方案。现在的做法是给一句明确的"请另存为 .docx"。
2. **Word 的页码是虚拟的。** docx 文件里根本没有页码信息，界面上的"第 N 页"
   是按每 1800 字符一页切出来的。这一点在解析结果里也标注了，不会假装是真实页码。
3. **文本框 / SmartArt 里的内容读不出来。** 如果整份文档的正文都在文本框里，
   会明确告知"没读到正文内容"，而不是静默产出 0 个知识点。

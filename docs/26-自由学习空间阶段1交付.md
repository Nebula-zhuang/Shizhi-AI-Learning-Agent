## 一、动工前装的依赖（你的第 2 点）

`python-pptx 1.0.2` 已装并声明进 `requirements.txt`。

顺带**把 PPT 解析器做完了**（不只是装上）：`app/ingestion/pptx_parser.py`，
`.pptx` 进 `SUPPORTED_EXTENSIONS`，13 条测试。

### 与 Word 解析器最大的区别：**页码是真的**

| | docx | pptx |
|---|---|---|
| 页码来源 | 文件里**没有**，只能虚拟分页（每 1800 字符一页） | **一张幻灯片就是一页** |
| 用户看到的"第 7 页" | 是我们切的，需要免责说明 | 就是他 PPT 里的第 7 页 |

所以 pptx 走 `pagination: "slide"`，不产出虚拟分页的警告。
这条有一条专门的测试守着（`test_pagination_is_slide_not_virtual`）——
它退化成 virtual 就意味着"溯源承诺"被破坏。

另外**演讲者备注会被读出来**（带 `（演讲者备注）` 前缀）：
备注里常放着正文没写的解释，对"读懂这份资料"是高价值内容。
加前缀是为了让后续抽取知道这不是投影内容。

`.ppt`（Word 97-2003 那种旧格式）走 `KNOWN_UNSUPPORTED`，给出"请另存为 .pptx"的具体提示。

## 二、数据模型（新增 2 张表）

### 为什么另建表而不复用 `sessions`

`sessions` 绑死了"一次围绕**某一个知识点**的学习"：

```
sessions: learner_id, document_id, knowledge_point_id, title, status, action_count
                              ^^^^^^^^^^^^  ^^^^^^^^^^^^^^^^^^
```

自由学习的对话**没有唯一知识点** —— 一轮里可能同时用到三个知识点、一份刚上传的文件、
一次联网搜索。硬塞进去要么让那两个字段全填 NULL（所有查询都要判空来区分类型），
要么"一个问题开一条 session"（那就不叫对话了）。

这也正好呼应你的 §13「不要把 Conversation / Knowledge / Memory 混成一张表」。

### 几个字段的取舍

- **`last_message_at` 而不是拿 `updated_at` 排序** —— 改标题会刷新 updated_at，
  于是"改个名字"就把对话顶到列表最前，与"最近聊过"的直觉不符。
- **`message_count` 冗余存** —— 列表页要显示聊了多少轮；只有一个写入点，没有不一致风险。
- **`sources` / `citations` / `status_trace` 用 JSON** —— 它们是给右侧面板展示的**摘要**，
  形状会随能力增减而变。但**工具原始入参出参与模型原始响应不进这里** —— 那些进日志。
  **对话表是给人看的。**
- **`status_trace` 特意落库** —— 状态是流式过程中推给用户的，
  刷新后如果只剩答案，"它到底查没查"就无从判断了，而这恰恰是用户最关心的。

⚠️ 踩坑记录：`content` 字段最初写成 `String(20000)`，MySQL 直接报
`1074 Column length too big (max = 16383)` —— utf8mb4 下每字符 4 字节，
VARCHAR 单列上限只有 16383。改用 `Text`。

## 三、API（新增 6 个）

```
GET    /api/study/conversations                          我的对话列表
POST   /api/study/conversations                          新建
PATCH  /api/study/conversations/{id}                     重命名
DELETE /api/study/conversations/{id}                     删除
GET    /api/study/conversations/{id}/messages            历史消息
POST   /api/study/conversations/{id}/ask                 提问（SSE 流式）
GET    /api/study/capabilities                           能力自检
GET    /api/study/attachments                            可选资料（"从资料库选择"用）
```

（上面 8 行对应 6 个**路径**，方法是复用的。）

### SSE 事件

```
status     {"text":"正在翻你的资料…"}      ← 自然语言状态，**后台真的在做那件事**
delta      {"text":"JVM 是"}               ← 正文增量
source     {kind:"knowledge_base",…}       ← 用到的资料片段
citation   {kind:"web",title,url}          ← 引用来源
done       {capabilities,sources,citations,status_trace,degraded_reason}
error      {"text":"…"}                    ← 一律人话，不带堆栈
```

**没有假进度**：每一条 status 都对应后台真的执行了那一步。

### 越权防护

- 所有查询强制带 `learner_id`；服务层**不提供**"按 id 单独查"的方法，
  只提供 `get_owned(id, learner_id)` —— 从签名上堵死"忘记加归属条件"这条路。
- 检索时把 `document_ids` 限定在该用户的资料内，显式传入的 id 也要与归属集取交集。

## 五、Free Study Agent 的路由

### 为什么有一个"启发式快通道"

你要求「简单问题一次 LLM 调用即可」。而"先问模型该不该检索、再生成"天然是两次调用 ——
对"什么是 JVM"这种问题，第一次调用完全是浪费。

所以先用确定性规则过滤掉一眼能定性的：

| 情况 | 路由 | 模型调用次数 |
|---|---|---|
| 没提资料、没时效词 | `general` | **1 次**（不调决策模型） |
| 提了"我的资料/上传的文件/第 X 章" | `knowledge_base` | 2 次 |
| 含时效词 / "帮我查一下" / 版本号 | `web_search` | 2 次 |
| 拿不准（如带附件但没指代） | 交给模型判断 | 2 次 |

规则写在代码里而不是提示词里，因为**"要不要花一次调用"本身是成本决策，不该由模型来定**。

### 你需求里逐字列的五个例子，实测路由

```
什么是 JVM？                    → ['general']         ✓
帮我解释一下这个 Java 代码。      → ['general']         ✓
这张图片是什么意思？              → 交给模型判断         ✓（有附件）
帮我分析这个 PDF。               → ['knowledge_base']  ✓
根据这个文件给我讲讲第三章。       → ['knowledge_base']  ✓
这个知识点和我之前学的有什么关系？  → ['knowledge_base']  ✓
帮我查一下 Java 25 的虚拟线程。   → ['web_search']      ✓
```

⚠️ 最后一条**一开始漏判了**：`"Java 25"` 这种裸版本号没被时效信号识别到，
被判成了 `general`。补了两条规则（显式搜索意图 `查询一下/搜一下`、产品名+版本号），
现在对了。这条漏判正对应你需求里举的例子，所以值得单独说。

### 联网时说真话

不联网时给模型的素材段是**一段明确的禁令**，而不是空白：

> **不要出现「我上网查了」「网上资料显示」「据报道」这类表述。**

留空会让模型自己脑补"大概是没有资料，我自由发挥吧"，
而它发挥出来的恰恰是"根据我查到的情况…"。

**禁令在"压根没打算联网"时也要给** —— 这种情况更隐蔽。

## 九、一个需要你决定的隐私问题

验收时发现：**清掉会话 cookie 后访问，能看到 1 个对话**。

原因：`current_learner_id` 在未登录时回退到 `DEFAULT_LEARNER_ID = "local"`，
而演示账号 demo 的 `learner_id` **也是 `local`** —— 两者是同一个身份。

这是 **P6 既有的设计**（对资料、学习状态同样成立），不是阶段 1 引入的。
它支撑了"不登录也能用"的体验。

但你的需求 §11 写的是「不同用户不能看到其他人的对话」。现在的情况是：
**未登录访客 = 默认学习者 = 演示账号**。

我没有擅自改全局鉴权（那会影响 P1-P6 的所有数据接口）。三个可选做法：

1. **保持现状** —— 演示场景最省事，未登录就是"本机这个学习者"
2. **自由学习要求登录** —— 只给这一组接口加 `require_user` 依赖，不影响其他页面
3. **匿名访客分配独立身份** —— 用 cookie 生成临时 learner_id，改动最大但对所有页面都更好

我倾向 2（改动小、正好命中你"对话不能被别人看到"的诉求）。你定。

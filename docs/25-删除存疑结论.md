# 删除「存疑」结论

> 日期：2026-09-20
> 用户反馈：资料存疑程度过高，删去存疑功能，保留联网搜索
> 已确认范围：**连判定一起删**（不只从界面撤掉）

---

## 〇、实际数据比反馈里说的更严重

你在界面上看到的是 C050.pdf 的 **27 条存疑**。查真实库：

| | 迁移前 |
|---|---|
| `verify_status` | unverified 9 / trusted 95 / **suspect 67** / **conflict 3** |
| `knowledge_checks.verdict` | passed 236 / **suspicious 91** / skipped 214 / unsupported 5 |

**67 + 3 = 70 / 174 个知识点（40%）带着警示标记。** 你的判断是对的。

---

## 一、"存疑"为什么该删，而不该调阈值

它的产出规则全是**软信号**：

- L1 规则：句子带通识引导词、但在原文里找不到依据
- L2 模型自评：模型认为"说得过头了"
- L3 联网：没搜到与该知识点明确一致的表述

**一个每两三条就命中一条的警示标签，用户学会的不是"去查那几条"，
而是"这个标签没用"** —— 于是真正有问题的少数几条也一起被无视了。

阈值调到多少都躲不开这个矛盾：**软信号的信噪比本身不足以支撑一个用户可见的结论。**

### 那为什么还留着联网搜索？

因为**搜索能力**和**对搜索结果的解读**是两件事。
搜索本身没问题（实测可用、返回真实结果），有问题的是"没搜到一致表述"被翻译成了"这条有出入"。

搜索能力完整保留，已经交给新的自由学习 Agent 用。

## 二、改动清单

### 结论层（后端）

| 改动 | 说明 |
|---|---|
| 删 `CheckVerdict.SUSPICIOUS` | 4 处生产者全部改为 `UNSUPPORTED` |
| 删 `VerifyStatus.SUSPECT` | 状态只产出 `trusted` / `unverified` 两种 |

**关键**：生产者从 `suspicious` 改判 `UNSUPPORTED` 不是降级，是**变准确**——
原来的含义本就是"我们没查到依据"，那就如实说"没找到依据"，而不是暗示"这条有问题"。

### 顺带纠正的一个语义错误

老汇总逻辑：

```python
if UNSUPPORTED in verdicts:  return CONFLICT   # 有出入
```

**"找不到依据"和"有出入"是两件事。** 前者是关于**我们**的事实（没查到），
后者是关于**知识点**的事实（它跟别人说的不一样）。拿前者冒充后者，
就是在冤枉知识点 —— 这正是那 70 条警示的来源。

现在 `UNSUPPORTED` 不再升级，如实停在"还没核对"。
`CONFLICT` 保留为枚举值（历史数据要能读），但**当前不产出** ——
和 `OUTDATED` 一样的处理方式，等有"外部证据与资料直接矛盾"的判断手段再启用。

### 顺带修掉的两个真 bug

**① `ERROR` 与 `UNSUPPORTED` 被混成了一个**

L1 的 error 级失败（**来源块不存在**、**没有页码**）原本也判 `UNSUPPORTED`。
但这两件事完全不同：

```
ERROR        核对**没能进行** → 我们不知道
UNSUPPORTED  核对进行了，但没找到依据 → 我们知道结果
```

现在 error 级判 `ERROR`。

**② 模型能越过缺失的来源去"背书"**

删掉 `UNSUPPORTED → CONFLICT` 之后暴露出一个隐藏漏洞：
一个连来源块都不存在的知识点，只要模型层（**在看不到原文的情况下**）说一句"忠实"，
就会被评为"可信"。

另外原条件本身也写错了：

```python
# 意图：通过必须来自非规则层（规则层只查格式，背书不了内容）
if PASSED in verdicts and any(check_type != RULE):   # ← 两个条件可以来自不同层
```

`[规则层通过, 联网层说没找到依据]` 会被判成"可信"。
两个条件必须落在**同一条** draft 上 —— 已修。

现在：
```python
if 规则层有 ERROR:                       return fallback   # 前提不成立，结论不算数
if 存在(非规则层 且 PASSED)的 draft:      return TRUSTED
return fallback
```

### 界面层（前端）

| 改动 | 位置 |
|---|---|
| 删 `suspect` 图例项 | 知识地图图例从 4 项减到 2 项（可信 / 还没核对） |
| 删 `suspect` 描边色 | 节点不再有橙色警告态 |
| 「存疑」文案删除 | `VERIFY_STATUS_LABEL` / `CHECK_VERDICT_LABEL` |
| 「原文里没写」降色 | 从砖红（警报色）降到赭 —— 它不是错误 |

`conflict` / `outdated` 的映射**保留**（保留位），避免历史数据渲染成裸状态码。

### 数据迁移（`0008_drop_verify_suspect`）

```sql
UPDATE knowledge_checks  SET verdict = 'unsupported' WHERE verdict = 'suspicious';   -- 91 行
UPDATE knowledge_points  SET verify_status = 'unverified'
       WHERE verify_status IN ('suspect','conflict');                                -- 70 行
```

**`downgrade` 故意抛 `NotImplementedError`。**
合并之后无法区分"原本是 suspicious"和"原本就是 unsupported"，
任何"还原"都会是编造的 —— **一个撒谎的 downgrade 比没有 downgrade 更危险。**
需要重新得到结论就跑一次校验。

|---|---|---|
| 知识点状态 | unverified 9 / trusted 95 / **suspect 67 / conflict 3** | **unverified 79 / trusted 95** |

### 界面

C050.pdf 的核对结果：

```
迁移前：可信 80 / 存疑 27 / 有出入 1
迁移后：可信 80 / 还没核对 28
```

浏览器实测：界面里已无「存疑 / 有出入 / 可能过时」字样 ✅ · 控制台零错误 ✅

### 测试

| 项 | 结果 |
|---|---|
| 后端全量 | 退出码 **0** |
| 前端单测 | **55 / 55** |
| typecheck / 构建 | ✅ / ✅ |
| 新增测试 | 守 4 条不变量（见下） |

新增的 4 条断言守的是这次改动的核心不变量：

1. `unsupported` **不许**变成 `conflict` —— "没查到"≠"有出入"
2. 汇总**只产出** `trusted` / `unverified` —— 防止警示状态悄悄长回来
3. 规则层 `ERROR` **阻止** `trusted` —— 前提不成立时，模型说通过也不算
4. `CheckVerdict` **不许再长出** `SUSPICIOUS` —— 防止有人"顺手加回来"

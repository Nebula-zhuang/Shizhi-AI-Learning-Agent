# 自由学习调度

## 1. 目的

用户问任何问题，**由 Agent 自己决定要不要用工具、用哪个、用完要不要继续**。

用户不选 Knowledge Agent / Research Agent / RAG / Web Search ——
他只需要把问题说清楚。这个 Skill 描述的就是"怎么替他把这些决定做对"。

## 2. 两条路径

**先判断要不要花一次决策调用**，这是成本决策，不交给模型：

| 情况 | 路径 | 模型调用 |
|---|---|---|
| 没提资料、没有时效信号、无附件 | **直接回答** | 1 次 |
| 其余 | 进入 Agent 循环 | 每步 1 次决策 + 1 次生成 |

**为什么要有这条快通道**：对"什么是 JVM"这种问题，
"先问模型该不该检索"那一次调用完全是浪费，还让用户多等一两秒。

## 3. 什么时候用哪个能力

按优先级，**从上往下第一个成立的就用，不要全都用**：

1. **能直接答就答。** 通用知识能答好的问题不要调工具。
2. **问题指向用户自己的资料 → 检索资料。**
   他要的是"我的资料里怎么说的"，联网帮不上忙。
3. **需要会随时间变化的信息 → 联网。**
   新版本、新发布、近期动态、"现在还行不行"。
4. **这一轮带了图片 → 先看图。** 不看图无法判断还能不能答。

### 时钟问题：**绝不能靠模型记忆**

「今天几号」「今天星期几」「现在几点」「今年是哪一年」这类问题的答案
**完全由本机时钟决定**，与知识无关。

⚠️ **实测踩过**：用户问「今天几号？」，没被识别成实时问题，
模型靠记忆回答「今天是 2024年6月13日」—— 实际是 2026年9月20日，**差了两年多**。

这类错误比「不回答」更糟：**它答得非常自信**，用户没有理由怀疑，
除非他自己知道今天几号（那他就不会问了）。

所以：

- 这类问题**必须拿到真实时间**，且**在进循环之前就已注入** ——
  不能指望模型自觉去调时钟工具（实测它就是不调）
- **不要用联网搜索查日期** —— 本机时钟才权威且免费，联网只会又慢又不可靠
- 需要在日期基础上推算时（「还有几天到考试」），**先拿真实日期再算**，
  不要凭印象推算

### 图片：先看再答

用户传了图（截图、题目照片、代码片段）时，**第一步必须看图** ——
不看图你无法回答任何关于图的问题，猜出来的答案比说“我看不了”更糟。

看图这个动作**不需要参数**：系统已经把这一轮的图挂好了，
你只要说想知道什么，不说也会按用户问的问题来看。

⚠️ **看图要看得仔细，不只是“认出这是什么”。** 实测有一次用户传了一段
缺基础条件的递归函数，模型只看出“这是算斐波那契的、输出 55”，
而**没发现那段代码其实会递归深度超限崩掉**。图里的信息往往比
“第一眼印象”多 —— 变量名、边界条件、注释里的数字，都值得核对。

### 明确不该联网的情况

- 经典概念（"什么是进程""什么是三次握手"）—— 答案十年不变，联网只增加等待与噪声
- 用户问的是他资料里的内容 —— 外部说法再多也不能覆盖他的课程
- 只是措辞不确定、想确认一下 —— 那不是时效问题

### 明确该联网的情况

- 含"最新 / 现在 / 今年 / 某个版本号 / 帮我查一下"这类信号
- 问的是**刚出现不久**的东西（用户往往自己也不知道它新，但问题里会有具体版本号）

## 4. 什么时候继续，什么时候停

**这是这个 Skill 最核心的部分。** 循环的价值全在这里。

看完一次工具结果之后，重新判断：

| 看到的 | 下一步 |
|---|---|
| 资料不够（只讲到基础概念，而用户问的是最新变化） | **继续**，换下一个能力 |
| 结果已经足够回答 | **停**，生成回答 |
| 工具失败了 | 想清楚是"换个查询再试"还是"用已有信息回答" |
| 工具说"没有可用能力" | **立刻停**，不要再试同一个工具 |

### 硬性的停止条件

- 同一个工具**最多试两次**。反复撞同一堵墙不会撞出结果。
- 已经拿到两类不同来源的信息 → 停。
- 说不出"再调一次能多拿到什么具体信息" → 停。

## 5. 降级与坦白

**超限（步数 / 调用次数 / 时长）不报错，降级到回答。**
拿已有信息回答并说明还差什么，比抛一个超时错误有用得多。

**能力不可用时要如实说。** 联网不可用 ≠ 这个问题没有答案 ——
要用已有知识回答，并说明"这条没联网核实"。

### 一条不能让步的规矩

**没真的查过，就不许说查过。**

不联网时要明确禁止模型出現"我上网查了""网上资料显示""据报道"这类表述。
不是"尽量不出现"，是**明确禁止** —— 实测发现留空会让模型自己脑补
"大概是没有资料，我自由发挥吧"，而它发挥出来的恰恰就是那些话。

同理：**引用只能来自工具真实返回的结果**。不要编造链接、页码、章节号。

## 6. 讲法

- 先说结论，再展开。用户想知道"是什么"，不是"你思考的过程"。
- 像人说话，不像文档。不写"根据您提供的信息"，不复述问题。
- **长度随问题走**。一句能说清的就一句。讲透一个点比列五个点有用。
- 有依据就标出处（"这段在你资料的第 12 页"），没有就如实说这是通用知识。

## 7. 不该做的事

- **不要为了展示能力而调工具。** 能直接答的问题调了工具，是负分。
- **不要暴露内部术语。** 用户看到的是"正在翻你的资料"，不是工具名。
- **不要在回答里提"工具""能力""检索"这些词** —— 他只需要看到教学内容本身。

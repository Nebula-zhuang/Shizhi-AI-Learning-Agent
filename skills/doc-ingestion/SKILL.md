# 资料解析与分块

## 1. 目的

把**任意格式**的学习资料，转成**统一、可溯源**的结构化文档，并切成带页码的语义块。

这个 Skill 是全链路的地基：知识点抽取的粒度取决于分块质量，知识点的页码溯源取决于
解析阶段是否忠实保留了位置信息。**解析阶段丢失的页码，后面任何阶段都补不回来。**

## 2. 格式分派

| 扩展名 | 解析器 | 策略 |
|---|---|---|
| `.pdf` | PyMuPDF | 逐页提取文本块；并行提取内嵌图片资源 |
| `.txt` | 文本解析器 | 编码探测后按空行分段 |
| `.md` `.markdown` | 文本解析器 | 识别标题层级，作为分块边界 |
| `.png` `.jpg` `.jpeg` `.webp` | 图片解析器 | 作为单页单图资源保存 |
| 其他 | — | 明确拒绝，返回支持的格式列表 |

**编码探测顺序**：`utf-8` → `utf-8-sig` → `gb18030` → `latin-1`（兜底）。
选第一个能完整解码且不出现替换字符的编码；全部失败则用 `utf-8` + `errors="replace"` 并记 warning。

## 3. 统一文档结构（契约）

所有解析器必须产出同一个结构，下游只认这个结构，不关心原始格式：

```json
{
  "document_hash": "sha256:...",
  "file_name": "操作系统原理-第3章.pdf",
  "file_type": "pdf",
  "page_count": 12,
  "pages": [
    {
      "page_no": 1,
      "has_text_layer": true,
      "blocks": [
        { "type": "heading", "text": "3.1 进程的概念", "level": 2, "bbox": [72, 96, 420, 118] },
        { "type": "text",    "text": "进程是程序的一次执行过程……", "bbox": [72, 130, 520, 210] },
        { "type": "figure",  "image_path": "images/p1_0.png", "caption": "图 3-1 进程状态转换",
          "width": 640, "height": 320, "bbox": [140, 240, 480, 400] }
      ]
    }
  ],
  "meta": {
    "parser": "pymupdf",
    "parser_version": "1.24.x",
    "image_count": 4,
    "warnings": [
      { "code": "NO_TEXT_LAYER", "page_no": 7, "message": "第 7 页无文本层，疑似扫描件，P1 未启用 OCR" }
    ]
  }
}
```

**块类型**：`heading`（标题）/ `text`（正文）/ `table`（表格）/ `figure`（图片）/ `formula`（公式）

### 3.1 页码是硬契约

- `page_no` 从 **1** 开始，不是 0。
- 每个块都必须能追溯到 `page_no`，`bbox` 可选但**有则必须保留**。
- 下游的知识点页码**只能**由块的页码推导，禁止任何阶段编造页码。

### 3.2 图片资源约定

- 落盘位置：`<UPLOAD_DIR>/<document_hash>/images/p{页码}_{序号}.png`
- 在结构中只存**相对路径**（`images/p1_0.png`），绝对路径由上层拼接 —— 这样更换存储根目录时无需改数据。
- 图片同时登记在 `chunks` 中（`block_type=figure`），使知识点可以引用图片所在的页。

## 4. 解析规则

1. **合并同段落 span**：PyMuPDF 的 `get_text("blocks")` 之后，把同一 block 内被切碎的
   行重新拼成段落；行尾没有标点且下一行首字符为小写字母/汉字时视为续行。
2. **页眉页脚剔除**：位于页面上下各 8% 区域内，且**全文出现 ≥3 次**的文本判为页眉页脚。
   只出现 1-2 次的保留（可能是正文）。
3. **纯页码行剔除**：整块内容匹配 `^\s*[-—–]?\s*\d{1,3}\s*[-—–]?\s*$` 的直接丢弃。
4. **标题识别**：同时满足「字号大于正文中位数」或「匹配 `^第[一二三四五六七八九十百]+[章节]`
   / `^\d+(\.\d+)*\s` / `^#{1,6}\s`」且「长度 ≤ 40 字」→ 判为 `heading`。
   **但公式行必须先排除**（见下条）。
5. **公式行不得判为标题**：公式的字号往往比正文大，是最容易被"字号明显大"这条规则误判的一类内容。
   实测危害：一份含大量 LaTeX 的论文 PDF 里，`d x P x d x= ∑`、`== −−` 这类公式碎片
   被当成了章节名，于是 `heading_path` 里出现垃圾标题 —— 而它是分块语境与知识点关系的共同依据，
   脏标题会让不相干的知识点归到同一节，并在图谱里凭空产生从属关系。
   两条判定依据（满足其一即认为是公式，不判标题）：
   - 含**私有区码位**（U+E000–U+F8FF）—— Symbol 字体符号被提取后的典型残留，正常文本不会有；
   - 含数学运算符（`= + − × ÷ ∑ ∫ √ ± ≤ ≥ ≠ ∂ ∞ ∈ ∀ ∃ → ← ↔ ^`）且汉字少于 4 个。
   > 运算符集合**刻意不含** `.` `-` `_` 与括号 —— 它们在「3.1 进程的概念」「3-1 节」这类
   > 正常标题里很常见，放进来会误伤。
6. **图片过滤**：宽或高 < 80px 的跳过（图标、分隔线）；同一页内像素完全相同的图只留第一张。
7. **公式内容**：PyMuPDF 无法可靠识别公式区域，统一按 `text` 处理并在 `warnings`
   记 `FORMULA_NOT_EXTRACTED`（保留原文，不做 LaTeX 转换）。注意区分：本条第 5 项管的是
   **不要把公式当标题**，本条管的是**公式正文照样保留**。
8. **空块丢弃**：去除首尾空白后为空的块不写入。

## 5. 分块规则

| 参数 | 默认值 | 说明 |
|---|---|---|
| 目标长度 | 600 字符 | 常规块的目标值 |
| 上限 | 1200 字符 | 超过则强制切分 |
| 下限 | 150 字符 | 低于此值向后合并 |
| 重叠 | 80 字符 | **仅在同一章节内**重叠，跨章节不重叠 |

**边界优先级**（从上到下依次尝试）：
1. 标题（`heading` 块）—— 最高优先级，标题必开启新块
2. 段落边界（空行）
3. 句末标点（`。！？；.!?;`）
4. 强制按上限截断（记 warning `FORCED_SPLIT`）

**不切断的内容**：`table` 与 `figure` 块自成一块，即使超过上限也不切（记 warning `OVERSIZE_BLOCK`）。
理由：被切断的表格对知识点抽取是噪声，危害大于超长。

**跨页规则**：允许一个块跨页（同一章节内），此时记录 `page_start` 与 `page_end`。
不允许跨越章节边界拼接。

## 6. 输出

每个 chunk 包含：

```json
{
  "chunk_index": 3,
  "content": "……",
  "page_start": 2,
  "page_end": 2,
  "block_type": "text",
  "heading_path": ["第3章 进程管理", "3.1 进程的概念"],
  "char_count": 587,
  "token_estimate": 412
}
```

`heading_path` 是**面包屑**，用于给知识点提供语境，也是前端展示归属位置的依据。

## 7. 失败与降级

| 情况 | 处理 |
|---|---|
| 文件加密 / 损坏 | `parse_status=failed`，错误信息对用户可读（"PDF 已加密，无法解析"） |
| 整个 PDF 无文本层 | `failed` + `hint`："该文件疑似扫描件，P1 未启用 OCR" |
| 部分页无文本层 | 正常继续，记 warning，`parse_status=ready`（带 warning） |
| **文本层存在但内容不可读** | 记 warning `SUSPECT_TEXT_LAYER`。有文本层不等于文本可用 —— 字体缺少字形映射或编码错乱时，提取出来可能全是 `·`、`□`，下游抽取会**静默返回空结果**。判定方式：可读字符（汉字/字母/数字）占比低于 50% 且文本长度 ≥50 |
| 单个块解析异常 | 跳过该块，记 warning，不中断整体 |
| 文件超过大小/页数上限 | 上传阶段即拒绝，不进流水线 |

**核心原则：局部失败不能导致整体失败。** 一份 50 页 PDF 有 2 页出问题，剩下 48 页照样要产出知识点。

**为什么要有「文本层存在但不可读」这一条**：这是实际踩过的坑 —— 用默认西文字体生成的 PDF，
中文字符没有字形，提取回来全是 `·`。此时解析"成功"、分块"成功"，
但知识点抽取会安静地返回空数组，用户只看到一个空列表，完全无从判断是自己资料的问题
还是系统的问题。加上这条检测后，界面会明确提示"提取出的文字中可读字符仅占 3%"。

## 8. 验收标准（P1）

- [ ] PDF 逐页提取文本，`page_no` 与原文一致（人工抽查 3 页）
- [ ] 页眉页脚被剔除，正文段落未被误删
- [ ] 内嵌图片被提取到 `images/` 并在结构中登记，尺寸过滤生效
- [ ] TXT（含 GBK 编码）与 MD 走同一套输出结构
- [ ] 分块无空白块、无跨章节错误拼接，表格未被切断
- [ ] 每个 chunk 都有 `page_start` / `page_end`
- [ ] 含 1 页无文本层的 PDF：其余页正常产出，warning 可见
- [ ] 加密 PDF：`failed` 且错误信息可读，不影响其他文档
- [ ] 同一文件重复上传：命中去重，不重复解析

## 9. 与其他 Skill 的边界

- **本 Skill 不做**：知识点判断、语义理解、内容摘要、OCR、公式转 LaTeX。
- **下游**：`knowledge-extraction` 消费本 Skill 的 chunks，不得反向依赖原始文件格式。
- **P3 复用**：RAG 的向量化直接对 chunks 建索引，因此本 Skill 的分块质量同时决定检索质量。

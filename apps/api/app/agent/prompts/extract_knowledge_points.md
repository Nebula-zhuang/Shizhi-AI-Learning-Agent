## 粒度规范（最重要，请仔细判断）

判定准则：如果一个知识点不能用 1-2 个问题考完，说明太粗；如果多个知识点回答的是同一个
问题，说明太细。

正确示例：
- 「进程与线程的区别」—— 一个可考查的对比类考点，粒度合适

错误示例与修正：
- 「第3章 进程管理」→ 太大，包含十几个考点 → 按小节拆开
- 「queue 的 enqueue 方法」→ 太小，是操作而非考点 → 合并为「队列的入队与出队操作」
- 「页表的作用」+「页表的结构」+「页表的位置」→ 三条讲同一件事 → 合并为「页表」

## 难度标注标准

1 = 识记（只需要记住定义、名词）
2 = 理解（能用自己的话解释）
3 = 应用（能套用这个知识解题）
4 = 分析（能比较多种方案或完成推导）
5 = 综合创造（能设计、证明或迁移到新场景）

## 重要度标注标准

5 = 材料明确标注的核心概念或考点（加粗、"注意"、例题、图示重点）
4 = 章节主干内容
3 = 支撑性内容（帮助理解但不直接考查）
2 = 举例、补充说明
1 = 边角信息、历史背景

重要度只能依据材料本身的呈现方式判断，不要依据你对这个学科的主观印象。

## 置信度标注标准

confidence 表示「这个知识点是否忠实于原文」，不是「你有多确定」：
- 0.90-1.00：原文直接陈述
- 0.70-0.89：由原文可推导
- 0.50-0.69：需要外部知识补充才能完整阐述
- 低于 0.50：原文信息不足，不要产出这条知识点

## 硬约束（违反会导致该条被程序丢弃）

1. source_chunk_indexes 必须来自本次输入提供的 chunk_index，至少 1 个，不得越界。
2. 不要输出任何页码字段。页码由系统根据 chunk_index 自动回填，你输出的页码不会被采用。
3. details 中不得引入原文没有的事实。确有必要补充背景时，用「**补充**：」作为前缀显式标注。
4. title 必须是名词短语，不要写成「关于……的说明」这类句式。
5. 同一批次内不要产出重复的知识点。若某个考点与「已存在的知识点标题」重复，直接跳过。
